# 04 交互状态与文案

触发：提交、取消、返回、加载、失败、离线、权限反馈或文字修改。页面具体动作以[DES-10](../../../会议室录音系统_PRD_v1.3/docs/design/DES-10-页面级设计与交互规格.md)为准；状态以[STATE-01](../../../会议室录音系统_PRD_v1.3/docs/rules/STATE-01-业务对象与状态规则.md)、范围以[ACL-01](../../../会议室录音系统_PRD_v1.3/docs/rules/ACL-01-角色权限与数据访问.md)为准。

## 通用反馈矩阵

| 状态 | 用户应知道什么 | 操作约定 |
| --- | --- | --- |
| 首次加载/局部刷新 | 正在加载哪部分 | 保留上下文；不要闪成“没有数据” |
| 首次空/筛选无匹配 | 暂无记录还是搜索无匹配 | 给合理下一步；保留筛选条件 |
| 提交中 | 操作正在处理 | 禁止重复提交；必要时锁定相关动作 |
| 提交失败 | 哪步失败、输入是否保留 | 错误留在页面/字段旁，允许有条件原样重试 |
| 版本冲突 | 数据已被修改 | 保留草稿，重载/对照，不静默覆盖 |
| 未登录/失效/无权/撤权 | 能否重新登录或申请访问 | 清理受控内容；不能泄露标题/计数；鉴权仍由接口执行 |
| 离线 | 哪些本地动作可继续 | 录音保留与等待补传分开；新扫码需联网 |
| 未知发送结果 | 结果尚未确认 | 管理员核查，不用“失败”诱导重发 |

正常自动流水线不增加人工核对或确认发送。关键保存失败不是几秒消失的toast；需要持续说明资料是否保住、谁可以做什么。

## 表单、弹层与会话

输入始终有可读标签，placeholder只作示例。必填/格式错误靠近字段；目标交互为提交后定位首个错误，修正时保留其他输入。

取消/返回的结果要明确。目标规范要求未保存更正有退出保护；当前样板仍存在直接关闭可丢草稿的路径，列为待实施，不因可点击即视为通过。确认弹窗用于有实质影响的账号/授权/分发变更，不给普通搜索增加确认。

长表单遵守02的固定标题/操作区规则。键盘焦点约束、Esc、返回和关闭后的焦点恢复要实际检查，不能只依赖组件库宣称支持。

切换用户清除前一人内容、草稿、媒体状态和受控缓存；会话过期关闭权限弹窗。当前原型不把草稿写入持久存储，正式草稿恢复需在同一身份且仍有权后进行。错误与身份过期应走统一请求层。

## 业务术语与格式

- 使用“会议纪要”“逐字稿”“行动事项”“原始录音”；版本分“当前版本”“AI原稿”“群快照”。
- 保存、上传、整理、渠道接收分别表达；“渠道已接收”不等于每位成员已阅读。
- “保存更正，不重发”“添加只读授权”明确副作用；权限不足说明缺少何种能力，不展示堆栈、密钥或内部调试内容。
- 未确定负责人/期限分别显示“负责人未明确”“期限未明确”；不自行推断实名或日期。
- 时长复用[duration](../../src/domain/presentation.ts)，状态文案复用同文件statusLabels。日期/时区需在真实服务联调中统一；当前合成记录使用示例日期，不可作为业务时间准确性验收。
- 演示、合成内容、无音频样本明确标注。实现细节放评审控制/文档，不塞入普通员工日常操作。

## 已知差距与验收

部分原型错误页仍合并“记录不可用/无权”，技术错误与403的最终文案分类需要补齐；草稿保护、首错误聚焦、完整键盘路径尚未全量验收。按[06](06-验收与维护.md)记录这些缺口，实施时写可观察结果测试。

# PRD-03｜转写、纪要与行动事项

## 1. 目标与输入输出

对经校验的音频生成中文逐字稿，再产生会议纪要与行动事项。处理是后台异步任务，平板不保存服务商密钥、不要求本地运行模型。云端、本地、混合待比较；未批准的外部服务不得接收真实录音或文字。

输出须区分原始音频、机器转写、机器纪要和人工确认版本。内容“已生成”不等于“已经核对”；失败不生成看似正常的空白成功结果。处理范围与数据去向独立于群分发模式，“仅归档”不自动允许外发 AI。

## 2. 内容结构与质量口径

| 产物/字段 | 要求 | 不允许的做法 |
| --- | --- | --- |
| 逐字稿片段 | 稳定片段标识、起止位置、正文、说话人标记、可选置信说明 | 无依据补齐听不清内容；伪造置信度 |
| 会议纪要 | 概述、议题与讨论、明确决定、未解决问题、相关事项 | 把建议写成已批准决定；仅有标题就算完成 |
| 行动事项 | 任务文本、负责人原文、可选对应账号、日期原文及可选解析值、证据、确认状态 | 凭职位或声音猜姓名；没有日期自动设明天 |
| 证据关联 | 转写版本、片段标识、起止位置；原文修改仍可追溯 | 只给脱离版本的字符偏移，修改后指错内容 |
| 处理记录 | 服务/模型/提示模板版本、处理地区声明、耗时、用量、错误 | 将真实音频/全文写进普通运行日志 |

相对日期只有在会议日期、时区和语义足够明确时转换；同时保留“下周三”等原句。设备时钟存疑或说话语义含糊时保持待确认。负责人提取与声纹实名识别不同，首期不建实名声纹库。

## 3. 功能需求

### REQ-AI-001｜处理准入与路由

**范围：P0；依据：建议细化。**

只有音频已归档且当前 AI 数据策略允许，才能排队处理。允许服务名单按音频和文字分别限制。无配置保持待配置；异常音频进入检查。每次外部调用前重新校验当前禁用/保密策略。

**反馈与例外：**不因为本地模型失败自动改用云端；数据已发送后不能宣称撤销能收回。

**验收：TC-AI-001。** 未经批准不切云，受限任务不外发；原音频保留。

### REQ-AI-002｜中文转写与时间定位

**范围：P0；依据：已确认逐字稿＋建议细化。**

输出可搜索的中文片段，并定位到可回放音频时间。分段识别可合并，但要处理重叠去重并保留源片段关联。厂商没有原生时间戳时不能伪造精确定位，应选合适服务或标注待对齐。

**反馈与例外：**听不清显示不确定标记；保留姓名、数字、单位原意。不得只返回翻译或提要当逐字稿。

**验收：TC-AI-002。** 全文与原音频可核对，位置有效，未识别内容显式标记。

### REQ-AI-003｜说话人分段与人工映射

**范围：P0；依据：建议细化。**

允许按会话区分说话人标签，标签不跨会议自动认定同一人。支持授权用户把标签映射为显示姓名；五人场景作为验收样本，不强迫算法输出五个标签。

**反馈与例外：**说话人分离能力不足时显示未知或待核对，不得为填满五人制造标签。重叠发言允许标记多人/不清楚。

**验收：TC-AI-003。** 不强制人数和实名，人工映射留痕且作用范围清楚。

### REQ-AI-004｜会议纪要内容

**范围：P0；依据：已确认纪要＋建议细化。**

基于指定转写版本生成结构化概述、议题、关键讨论、明确决定和未决问题。与源片段关联。机器稿清楚标注未经人工核对，不把问句、假设、否定或建议当成承诺。

**反馈与例外：**输入不足时显示无法充分总结及原因；不得编造会议标题中的业务信息。

**验收：TC-AI-004。** 决定有原文依据；否定与不确定性保留；无内容不虚构。

### REQ-AI-005｜行动事项提取

**范围：P0；依据：已确认行动事项＋建议细化。**

提取明确的待办，并保存任务说明、负责人原文、日期原文、对应证据。未明确负责人/期限时字段为空且标待确认。日期解析和账号映射须可人工确认；不得自动创建企业微信任务或考核。

**反馈与例外：**“我来处理”在说话人身份未知时不能映射到某员工；条件性承诺保留条件。

**验收：TC-AI-005。** 保留不确定项、不凭空派人；取消/条件语义正确。

### REQ-AI-006｜长录音与上下文完整性

**范围：P0；依据：建议细化。**

在批准的最长录音范围内可拆分处理，再汇总跨段决定与事项。记录覆盖了哪些片段，禁止默默截断后半场仍显示完整。重叠片段不得重复制造待办。

**反馈与例外：**超服务限额转适配处理或明确失败；不把“模型成功返回”作为全文已覆盖的证明。

**验收：TC-AI-006。** 结尾内容被覆盖，覆盖清单齐全，无重复事项。

### REQ-AI-007｜可恢复任务与计费控制

**范围：P0；依据：建议细化。**

转写和总结分开任务，保存输入指纹、处理版本与有界重试。总结失败仅重试总结；同一请求不无控制重复计费。服务超时但执行状态不明时应记录不确定状态并采用服务支持的查询或恢复策略。

**反馈与例外：**预算阈值超限暂停新付费任务，保留待处理会议；不删除原件以“解决”超额。

**验收：TC-AI-007。** 不重复完整转写；费用可追踪；超预算停止新外部调用。

### REQ-AI-008｜重新生成与版本冻结

**范围：P0；依据：建议细化。**

新的模板、转写修订或模型产生新版本，不覆盖历史。人工确认版本不会被后台重跑替换。已有分发绑定的内容版本保持不变；新版本需重新满足审核/发送规则。

**反馈与例外：**修订源逐字稿后把旧纪要标记可能过时；迟到任务结果不能覆盖更新的人工内容。

**验收：TC-AI-008。** 历史可查，人工版不被覆盖，旧发送指向原快照。

### REQ-AI-009｜录音内容不执行系统指令

**范围：P0；依据：建议细化。**

把录音和转写当作不可信业务输入。模型不得根据其中的指令访问网址、发消息、更改群、执行代码、泄露其他会议或修改权限。输出经结构校验与文本安全处理。

**反馈与例外：**纪要中的链接不自动访问；标题、转写、AI 输出都不能直接成为任意脚本或网页。

**验收：TC-AI-009。** 只是记录或忽略该话语，不发生系统操作，输出不会执行代码。

### REQ-AI-010｜热词与模板版本

**范围：P0；依据：建议细化。**

管理员可维护中文专有词和纪要模板，版本化并测试。模板只影响内容整理，不得带真实群密钥或形成自动授权。热词改善效果必须经样本对比，不强制所有服务具备同一特性。

**反馈与例外：**不支持热词的服务明确能力限制；模板变更默认只影响新任务，重跑旧会须显式操作。

**验收：TC-AI-010。** 版本可追溯，不改旧成果，不越过访问/外发策略。

### REQ-AI-011｜质量审核与空结果

**范围：P0；依据：建议细化。**

定义结果校验：字段结构、证据有效性、覆盖率、空结果、缺口和明显无依据内容。空白/仅噪声可形成“无可识别内容”，不编纪要；只要有原件仍能归档。

**反馈与例外：**低质量或不完整自动转待审核，不能按普通成功会议无提示自动发群。质量阈值见 ACC-01。

**验收：TC-AI-011。** 错误被识别、产物标记清楚，禁发或待审，不造假内容。

### REQ-AI-012｜成本与部署对比

**范围：P0；依据：已确认比较部署＋建议方法。**

同一批经授权样本可在获批准的云端、本地、混合候选上测转写、总结质量、时延和成本。记录真实版本与算力，不预填赢家。不要求首期同时维护全部路线。

**反馈与例外：**开发默认 mock，无真实付费；真实对比按单独批准的服务、资料范围和额度执行。

**验收：TC-AI-012。** 输出可复现的测量，不将估算当实测，未批准服务无调用。

# PRD-05｜分发与审核

## 1. 范围与必要前提

目标是向已授权的企业微信管理群单向推送摘要和入口，不读取群历史、不做群内对话机器人，不将会话内容存档作为本项目能力。目标组织和群必须实际具备消息推送入口及权限；创建路径参考 EXT-06，上线前由管理员实测。

群 Webhook 只作为发送凭证，不作为全文访问凭证。群内消息内容属于对该群受众的披露，不能用“详情页有权限”替代对摘要受众的审核。群成员变化由群负责人维护复核，不能假定单向 Webhook 能自动读取并持续核对群成员。

## 2. 策略字段及优先顺序

| 字段 | 产品含义 | 要求 |
| --- | --- | --- |
| 启用/环境 | 草稿、测试、正式与暂停 | 正式发送需全局授权开关和已批准目标 |
| 匹配条件 | 会议室＋可选会议类型/部门 | 不支持任意脚本；缺数据不由模型推测 |
| 模式 | AUTO、REVIEW、ARCHIVE_ONLY | 未配置不发送 |
| 目标组 | 有限个已批准连接 | 不接受平板或模型任意 URL |
| 内容 | 摘要结构、是否列事项、链接版本 | 禁止自动全文堆进群；保留版本标记 |
| 查看范围 | 授权用户/业务组 | 与群目标分别配置；群目标需受众复核 |
| 生效范围 | 新会议；待发会议需显式再评估 | 版本化，避免规则改动把历史会议批量发出 |

优先级定义在 STATE-01：删除/全局停发/收紧访问优先；本场保密或禁止发送优先于普通规则；已知不完整/低质量需审核；其余按最高明确优先级规则；同优先级冲突则阻断。匹配过程形成解释，不能依赖数据库自然排序。

## 3. 功能需求

### REQ-DIST-001｜三种分发模式

**范围：P0；依据：用户要求可配置＋建议细化。**

实现自动发送、审核后发送、仅归档。普通已配置会议在内容满足条件时自动推进；配置缺失进入未配置，保密限制进入禁止。生产初始禁发，测试仅预览。

**反馈与例外：**只归档不自动审核也不自动发群；未配置不能偷偷使用最后一个群。

**验收：TC-DIST-001。** 路由符合模式，无规则/仅归档零外发；自动模式无人工转发。

### REQ-DIST-002｜规则匹配与冲突

**范围：P0；依据：建议细化。**

按会议室、已提供的类型/部门和显式优先级匹配，按 STATE-01 处理冲突。展示命中规则、版本和原因。缺部门只能命中明确允许的默认规则，不猜测分类。

**反馈与例外：**同级多个不同结果阻断并通知配置负责人；无自动“取第一个”。

**验收：TC-DIST-002。** 各情况可解释，冲突不发，未出现猜测路由。

### REQ-DIST-003｜保密与动态收紧

**范围：P0；依据：建议细化。**

任何时点将会议设为更严格模式、删除或全局停发，都要在尚未发送的任务执行前拦截。已经提交到外部渠道的消息不能保证召回；系统保留披露记录及后续撤权。

**反馈与例外：**普通操作人员可收紧，不可扩大分享。仅归档、禁云、内容访问三个约束分别生效。

**验收：TC-DIST-003。** 未发任务取消/阻断；已发如实显示且不假称已收回。

### REQ-DIST-004｜审核绑定内容和目标版本

**范围：P0；依据：建议细化。**

审核通过绑定纪要版本、消息预览、目标集合和策略版本。内容或目标变化使原审核失效；原作者能否自审属于待批准配置，默认测试允许但标记，正式必须显式设定。

**反馈与例外：**审核意见与否决原因留痕；审核不是“以后所有版本都可发”。

**验收：TC-DIST-004。** 要求重审，旧批准不被用于新内容/新群。

### REQ-DIST-005｜可预览消息与内容限额

**范围：P0；依据：建议细化。**

生成会议时间、会议室、简短摘要、可选事项、版本、完整记录入口及 AI 提醒。模板确定性裁剪到渠道限制内，不在字符中间破坏中文；完整信息留受控页面。

**反馈与例外：**具体字节/频率限制由适配器按当前渠道文档核实；无需长文拆成大量群消息。低质量会议必须可见标记。

**验收：TC-DIST-005。** 长度合规且保留合法入口；文本不执行脚本；无静默漏掉版本/风险提示。

### REQ-DIST-006｜发送任务去重与多目标状态

**范围：P0；依据：建议细化。**

同会议＋内容版本＋目标＋发送类型建立稳定业务去重。重复完成事件只产生一个逻辑任务。多目标各自记录，不因一个失败重复发送已成功目标。

**反馈与例外：**人工补发需要新动作和理由，明确标记补发；不承诺外部渠道支持端到端恰好一次。

**验收：TC-DIST-006。** 成功目标不重复，失败目标独立恢复，重复事件不多建任务。

### REQ-DIST-007｜超时、限流与未知结果

**范围：P0；依据：建议细化。**

按真实渠道返回判定已接收、明确失败或结果待确认。明确未成功可有界重试；请求可能已送达但响应丢失时进入未知结果，默认不自动盲重发，交人工确认。

**反馈与例外：**发送成功显示渠道已接收，不显示已读。未知结果经确认重发可能重复，应告知操作者。

**验收：TC-DIST-007。** 任务为结果待确认，不因重启反复群发。

### REQ-DIST-008｜凭证和连接测试

**范围：P0；依据：建议细化。**

Webhook 由授权管理员录入受控服务端，保存后仅显示掩码与连接名。校验发送目标属于批准的渠道域与协议，防止任意地址访问。测试先显示目标和虚构内容，明确授权才真实发送。

**反馈与例外：**测试群和正式群隔离；日志/错误不得回显 URL 密钥。轮换凭证不自动把历史待发任务发送。

**验收：TC-DIST-008。** 非法目标被拒，凭证不泄露，真实测试需明确操作。

### REQ-DIST-009｜发送与阅读权限分离

**范围：P0；依据：建议细化。**

策略管理员明确群受众可接收的摘要范围，详情单独按登录对象授权。群名单不能从机器人 URL 推断；接收群与内部访问组的映射需人工登记、定期复核。

**反馈与例外：**正文访问被撤销时未来请求拒绝，但无法撤销群里已经看到的摘要或下载副本。

**验收：TC-DIST-009。** 发送不自动授予全文访问；无权用户看不到内容，受众复核记录存在。

### REQ-DIST-010｜修订后再发布

**范围：P0；依据：建议细化。**

已发送的纪要快照不覆盖。人工确认新版本后，可显式发布更正版，标注版本与更正说明；不得每次编辑自动重复发群。对未发送旧任务按版本失效规则取消。

**反馈与例外：**旧链接显示其原版本和存在新版提示，不把旧消息内容偷偷替换。

**验收：TC-DIST-010。** 普通编辑不发，更正可追踪，v1 快照仍能核对。

### REQ-DIST-011｜可解释的配置预演

**范围：P0；依据：建议细化。**

发布规则前选择合成样例或授权已有会议预演，只计算结果，不发消息。显示预计模式、目标、内容范围、审核和权限冲突。发布新规则默认仅作用新会议。

**反馈与例外：**重评历史待发会议须显式范围和数量确认，重新校验权限和审核。

**验收：TC-DIST-011。** 历史不突然群发，预演零外部发送，结果可解释。

### REQ-DIST-012｜异常告警与停发

**范围：P0；依据：建议细化。**

提供全局停发开关及异常列表；停发不阻断录音/归档。运维告警默认只包含编号、错误和受控入口，不把会议正文送到运维群。渠道故障不能依赖同一个已坏渠道作为唯一告警。

**反馈与例外：**停发后仍需处理外部已提交的未知结果；恢复时受控重评，不无条件清空全部队列。

**验收：TC-DIST-012。** 原件继续保存，新外发停止，后台可见异常且不泄露内容。

# PRD-07｜用户、组织与权限管理

版本：1.1-draft｜2026-09-20｜模块范围由 Alec 本轮“好的，加”确认；业务细项为待评审设计。

## 1. 目标与范围

为单公司会议记录系统提供独立的登录、用户、部门、角色、业务访问组和会议范围管理。平台管理员、业务授权者、编辑者、审核者和查看者可以由同一人兼任，但通过显式授权体现。首期不建设商业多租户、通用审批引擎或自定义权限脚本。

账号来源未选定；企业微信单点登录继续是可后置适配。使用企业微信群推送不表示已具备企业微信登录/通讯录权限。第一版要求身份模型兼容后续接入，不要求现在运行多套认证服务。

## 2. 页面与操作

| 页面 | 工作区与行为 | 首期边界 |
| --- | --- | --- |
| AUTH-01 登录 | 身份入口、失败/停用、退出和返回目标 | 原型选择虚构身份模拟，不收真实密码 |
| IAM-01 用户 | 搜索、新增、编辑部门、分配带范围的角色、停用 | 账号状态和人员历史分离 |
| IAM-02 组织 | 部门树、负责人、新增/编辑、依赖与停用 | 单公司；一个主部门；组织不自动赋内容权 |
| IAM-03 角色 | 固定权限目录、业务角色、成员和变更预览 | 系统保护角色只读；功能与范围成对 |
| IAM-04 访问组 | 跨部门成员、关联范围、成员变更 | 不是企业微信群；历史策略须明确 |
| IAM-05 会议授权 | 归属、角色、主体、历史边界、原因、撤销 | 受限会议显式授权；越权授予拒绝 |
| IAM-06 有效权限 | 选择人员/会议/动作查看来源与拒绝原因 | 无权元数据不泄露；原型固定样例 |
| IAM-07 授权审计 | 本次变更与访问轨迹 | 原型内存事件；正式持久审计另验 |

## 3. 原型演示数据

公司、部门、人名及所有身份均虚构。演示身份：账号管理员（用户/组织/业务角色配置、无正文权）、业务授权者（销售样例会议授权、无系统管理委派权）、会议查看者。原型角色权限目录可勾选，但自定义角色仅在权限预演器中生效；旧录音/纪要演示仍使用顶部角色切换，不代表已接上真实鉴权。

默认登录页展示三种演示身份。新增用户与授权只保留到刷新/重置；评审意见按原机制保存在本浏览器。批量导入、本地密码找回、企业微信认证、部门重组批量交接保留为正式需求，不在单文件原型伪造真实接入。

## 4. 功能需求

### REQ-IAM-001｜登录、退出与身份来源

**范围：P0；依据：模块已确认＋建议细化。**

内容后台必须登录；首次管理员一次性初始化，无公开自助注册。账号来源支持本地账号或获批统一身份，真实来源待 D-06/D-16 确认；外部身份用稳定标识关联本地用户，不按姓名/邮箱自动合并。退出、超时、停用后受控请求拒绝，登录成功返回原有权目标。

**反馈与例外：**本地账号路线需改密、重置、失败限速与恢复流程；外部账号在身份源处理密码，页面不可假装已同步。

**验收：TC-IAM-001。** 无内容泄露，身份不误合并；恢复流程不绕过授权。

### REQ-IAM-002｜用户创建与生命周期

**范围：P0；依据：模块已确认＋建议细化。**

管理员创建/导入用户，维护稳定用户标识、姓名、账号、主部门、状态、身份来源。停用代替直接删除，撤销会话；历史操作保留原操作者，不转嫁给接任者。最后一个有效初始化/恢复管理员不能被普通操作移除。

**反馈与例外：**拒绝重复账号、无效部门；恢复管理员按受控运维流程，不设共享后门。

**验收：TC-IAM-002。** 账号唯一而姓名可重复；停用新请求拒绝；最后管理员保护与历史身份保留。

### REQ-IAM-003｜组织结构与人员调动

**范围：P0；依据：模块已确认＋建议细化。**

单公司维护部门树、负责人、排序、启用状态；禁止自循环和祖先循环。停用部门前处理成员、子部门、会议/路由依赖；改名不重写历史归属快照。首期一个主部门，兼职需求确认后扩展。

**反馈与例外：**人员调动预览角色、访问组、历史会议和待审核事项影响；不因进入新部门自动开放历史。

**验收：TC-IAM-003。** 无循环/悬空归属；依赖未处理时阻止停用；旧范围按政策撤销，新增范围须明确。

### REQ-IAM-004｜角色与功能权限配置

**范围：P0；依据：模块已确认＋建议细化。**

系统提供固定权限目录，管理员创建/修改业务角色及分配用户。系统保护角色不可由普通角色编辑增加或移除关键系统权限；功能覆盖查看、播放、下载、导出、编辑、审核、发送、账号、组织、角色、授权、设备、审计。

**反馈与例外：**新增权限默认未选；禁用仍被引用的角色前先迁移授权，不删除历史授予证据。

**验收：TC-IAM-004。** 只接受权限目录项；成员影响可见；系统保护生效，审计可回溯。

### REQ-IAM-005｜功能和范围成对授权

**范围：P0；依据：模块已确认＋建议细化。**

授权记录绑定主体（用户/业务组）、角色、对象范围、生效时间及历史边界。每条授权独立判断动作与对象，多个有效授权仅合并已经满足条件的结果，不把一个角色的功能与另一个角色的范围交叉放大。

**反馈与例外：**停用、撤销、过期、受限会议约束优先；部门负责人身份不自动产生内容权限。

**验收：TC-IAM-005。** 财务可读不可编辑；所有内容渠道复用同一判断，不出现元数据旁路。

### REQ-IAM-006｜业务访问组与成员维护

**范围：P0；依据：模块已确认＋建议细化。**

访问组支持跨部门成员，组织结构和访问组独立。加入/移出成员需预览其关联授权、未来/历史资料范围；移出撤销该组带来的资格，保留其他合法独立授权并说明来源。

**反馈与例外：**组名不是企业微信群标识；不自动同步群成员，不允许停用账号通过组恢复访问。

**验收：TC-IAM-006。** 组授权按选定时间范围生效；独立授权不误删；停用优先。

### REQ-IAM-007｜单场会议授权与撤销

**范围：P0；依据：模块已确认＋建议细化。**

业务授权者可对其可委派范围内的会议设置负责人、部门、数据等级及明确授权记录；授权显示主体、角色、范围、历史边界、原因和影响。受限会议必须逐场/专门组显式授权；撤销下一受控请求生效。

**反馈与例外：**扩大内容权限与改发送群分别操作；变更使相关审核失效，不能靠编辑元数据直接开放记录。

**验收：TC-IAM-007。** 取消零变更；确认有审计；撤销立即约束受控入口，短效凭证残余窗口明确实测。

### REQ-IAM-008｜授权委派与防止自提权

**范围：P0；依据：模块已确认＋建议细化。**

账号维护、角色设计、内容授权、授予系统管理权分别检查。执行者只能在明确委派的功能与对象范围内授权，不得通过改角色、拉组、改部门或更换身份源给自己/他人扩大权限。首个管理员由一次性初始化获得初始管理资格，后续高权限授予走受控流程。

**反馈与例外：**系统管理员可兼任业务角色但须显式授予；不宣称能限制拥有全部主机与密钥的运维者。

**验收：TC-IAM-008。** 各路径均拒绝超范围授权；保护角色和最后管理员不可普通移除。

### REQ-IAM-009｜会议归属与匿名设备边界

**范围：P0；依据：模块已确认＋建议细化。**

平板设备身份不等于自然人；默认保持不强制每场登录/填部门。设备只确定采集会议室。部门来源不足时仅按已批准固定访问范围归档；依赖部门路由的会议进入待确认，不能由 AI 猜归属。没有批准默认访问范围时仅受控元数据待办可见。

**反馈与例外：**共享会议室流程、发起人识别方式待 D-17；后台认领只由有资格的人执行，登记认领时间/依据，不伪造录音发起人。

**验收：TC-IAM-009。** 未知归属不猜群/不扩权；录音上传可继续；认领与实际发起人分开记录。

### REQ-IAM-010｜历史访问与交接

**范围：P0；依据：模块已确认＋建议细化。**

新成员、调岗、组成员变化、授权延期需明确仅新会议/指定时期/明确历史会议；缺少历史政策时不自动追加历史授权。离职撤权与资料保留分开，会议负责人和待审事项按受控交接转移。

**反馈与例外：**历史资料归属按当时快照保存；已合法下载文件无法强制抹除，页面不承诺撤回。

**验收：TC-IAM-010。** 旧访问按批准规则撤销，未批准历史不可读，交接不篡改原操作者和纪要版本。

### REQ-IAM-011｜审核与分发职责

**范围：P0；依据：模块已确认＋建议细化。**

编辑、审核、发布、修改目标分别授权；是否允许自审由 D-05 显式确定，未设定时正式外发阻断。内容/目标/访问范围改变使对应审核失效。群摘要受众另行批准，不以全文登录代替摘要保密。

**反馈与例外：**收到群消息不自动获取全文权限；禁发限制不等于外部 AI 数据策略。

**验收：TC-IAM-011。** 缺配置/审核失效明确阻断；发送前复核实际受众和当前资格。

### REQ-IAM-012｜权限解释、审计与恢复

**范围：P0；依据：模块已确认＋建议细化。**

提供有效权限查询：说明账号、角色、授权来源、对象范围和拒绝原因，不向无权用户泄露会议标题。权限、登录、查看/下载和恢复事件保留身份、时间、对象、前后变化和原因；不记录密码/密钥/全文。恢复保留停用/撤销/删除标记。

**反馈与例外：**审计读取自身也受范围约束；审计写入失败阻断高风险授权，普通录音仍先本地保护。

**验收：TC-IAM-012。** 原因可解释且不泄露正文；高风险无痕变更被拒；恢复不复活账号权限。

### REQ-IAM-013｜配置预览与并发变更

**范围：P0；依据：模块已确认＋建议细化。**

角色、成员、组织和授权提交前显示受影响用户/会议/待办范围。扩大范围必须填写理由并明确历史边界；保存带版本，过期编辑拒绝并要求重新核对；取消不产生业务变更。

**反馈与例外：**预览结果与提交间发生权限收紧时重新校验，不复用过期批准。

**验收：TC-IAM-013。** 过期或已撤权请求拒绝；无丢失更新；取消无业务修改。

### REQ-IAM-014｜原型与正式实现边界

**范围：P0；依据：模块已确认＋建议细化。**

原型提供 AUTH-01 与 IAM-01至07 的合成数据流程；不采集真实密码，不接企业身份系统、不维护真实会话、不作安全保证。原型检查单与产品验收用例分别记录。

**反馈与例外：**开发必须在服务端重做身份和逐请求授权，不可把隐藏按钮或原型角色切换当作权限实现。

**验收：TC-IAM-014。** 原型明确演示边界；正式验收必须有真实请求拒绝证据，不能复用原型通过结论。

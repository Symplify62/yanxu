# DES-01｜总体技术方案建议

性质：根据PRD推导的技术建议，不是已批准技术栈或已存在代码。先检查实际工作区和可复用组件，再在技术决策记录中冻结方案。业务行为以PRD和规则为准，不让框架默认行为覆盖需求。

## 1. 逻辑架构

安卓平板录音/本地清单/上传队列 → 受保护的设备接入服务 → 私有原音频存储＋会议数据库 → 后台转写任务 → 总结及事项任务 → 审核/策略计算 → 企业微信发送适配器。网页后台通过同一身份与对象授权服务读取内容。独立运维记录、备份和恢复覆盖全链路。

首期倾向模块化单体后台加异步worker，不强制微服务、Kubernetes、MQTT或独立消息中间件。数据库中的任务、唯一约束和事务能满足首期时优先简单设计，但不能以内存任务冒充持久恢复。对象/文件存储可替换，只要私有访问、原件校验和恢复能力满足需求。

## 2. 模块责任与禁止跨界

| 模块 | 责任 | 不得承担 |
| --- | --- | --- |
| 终端采集 | 音频、本地状态、设备身份、自动上传 | 服务器AI/群秘密、历史全部正文 |
| 接入归档 | 认证、唯一会话、校验、接收收据 | 等AI成功才确认保存 |
| 内容处理 | 转写/总结适配、版本、质量检查 | 根据录音内容改权限或目标 |
| 记录服务 | 查询、编辑、证据、对象权限 | 公开裸文件地址 |
| 分发服务 | 规则、审批、消息快照、去重 | 假定第三方端到端恰好一次 |
| 管理运维 | 配置版本、元数据诊断、恢复 | 自动获得全部会议内容 |

## 3. 候选技术方向及选择原则

安卓：原生Kotlin是建议，UI可选原生组件或Compose；确认最终min/target SDK与平板支持矩阵。录音可复用经核验的开源核心，但必须理解其文件保护和生命周期。不得仅因为原项目编译通过就认定满足本PRD。

后台/网页：现有工作区能满足时复用；空项目由Codex提出两套以内可维护方案，比较团队运维、异步任务、对象权限、部署与许可，再冻结。没有强制指定芋道、Spring、Python、Node、React或Speakr，不要求为了审美重写成熟功能。

AI：统一Transcriber/Summarizer抽象与能力声明，不承诺所有服务具备时间戳、说话人分段或热词。先接mock，再选实际路线。外部服务调用必须经过批准列表和预算控制。

## 4. 关键一致性设计

接收端：先把完整资产与校验信息持久化，再提交会议接收状态；失败可补偿，但不能先返回成功后丢文件。后台任务与接收状态之间用可靠事务/outbox或等价机制，避免文件存在但永远没有处理任务。

处理端：任务以输入版本和服务配置指纹去重，记录尝试；迟到结果只对其原版本有效。编辑与审核采用乐观锁或等价并发校验。

发送端：业务任务唯一约束、消息冻结、每目标尝试记录、发送前重新授权。外部接收和本地记录不可能被普通数据库事务包成一个原子操作；超时进入UNKNOWN是需求，不可以靠无限重试掩盖。

删除端：先阻断公开使用和后续任务，再按清单清理当前资产。外部副本和备份窗口如实说明。恢复先恢复权限/删除/去重再开启业务。

## 5. 技术验证任务

SPIKE-01：目标AVD能否录制宿主输入；比较真实采音与注入模式，附配置。SPIKE-02：录音容器/分段方案的崩溃恢复窗口与间隙。SPIKE-03：单场最终最大时长与文件大小的上传恢复。SPIKE-04：候选开源项目编译/依赖/许可。SPIKE-05：AI同样本对比。SPIKE-06：企微测试群和受控记录页在管理者真实客户端访问。

每项产出实际运行命令、输入、结果、失败与建议；无设备或密钥时明确阻断点，不编造通过。冻结的技术决策至少记录：问题、候选、选择、理由、风险、反转成本、适用版本、批准范围。

## 6. v1.2 实施设计入口与部署边界

本文件维持架构和技术选择职责。完整阅读顺序见[DES-00](DES-00-实施设计总览与阅读地图.md)，任务实现见[DES-07](DES-07-后端模块与异步任务设计.md)，数据见[DES-08](DES-08-数据模型与一致性设计.md)。技术选择状态唯一登记在[DEC-01](../delivery/DEC-01-决策与实施准备清单.md)。

建议生产最小部署单元：HTTPS入口/网页与API、worker、数据库、私有资产存储、经批准AI服务、独立备份。API和worker可以来自同一代码仓库/构建，运行责任分开；存储与数据库不因小规模而公开到互联网。初期不用独立微服务替代清晰模块边界。

信任边界：公用平板仅是设备身份；浏览器和模型输出均不可信；业务API负责授权；后台worker也受数据策略约束；外部AI、企微消息、下载副本离开本系统控制后不能承诺撤回。所有出口在测试与正式环境分别配置。

技术选型比较只围绕维护经验、录音生命周期、持久任务、权限查询、中文搜索、部署资源和依赖许可。第一候选是复用公司可维护的成熟后台生态，第二候选是独立轻量后台；实际工作区和团队条件未知，未指定框架或版本。T-01调查后记录推荐、代价与反转成本。记录“框架名字”不能替代本文要求的故障和授权能力。

## 7. 跨模块变更影响

身份变化影响查询缓存、媒体、编辑、审核与待执行任务；采集编码变化影响上传清单、播放和ASR；正文版本变化影响事项证据与审核快照；保留规则变化影响本地清理、服务器资产、索引、导出和备份。修改这些基础契约必须同时检查调用方、旧客户端和相关测试，不只更新一个页面。

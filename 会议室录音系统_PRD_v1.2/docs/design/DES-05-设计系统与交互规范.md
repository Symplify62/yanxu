# DES-05｜设计系统与交互规范

版本：1.2-draft。建议设计基线，尚未实现组件库或通过产品视觉签核。对应 REQ-NFR-006、REQ-REC-010、REQ-LIB-002/005、REQ-IAM-004/007/013。业务状态和权限以STATE-01/ACL-01为准。

## 1. 三端共同原则

平板让操作者立即看懂是否正在录音、是否已保存；后台让审核者快速核对资料、版本与范围；手机记录页让接收者方便阅读、回听和理解无权反馈。共享文字语义、颜色含义和动作层级；网页与原生安卓分别实现控件，不强求代码共用。

产品正式名称/标识暂未签核，当前原型仍显示“会记”暂名。名称、工作台标题、安装包显示名和消息署名应在T-02一并统一。v0.2可作风格参考，不直接把其中所有尺寸作为正式规范。

## 2. 基础设计变量建议

| 类别 | 初始建议 | 实施规则 |
| --- | --- | --- |
| 主色/强调 | 延续原型深绿 #16735A | 只用于主要操作和选中，不代表任何任务都成功 |
| 背景/正文 | 页面 #F5F6F7、纸面 #FFFFFF、正文 #182A27 | 辅助文字、边框、禁用态使用语义变量并检查对比度 |
| 状态 | 成功绿、警示琥珀、失败红、信息蓝 | 必须同时提供文字/图标；不能只看颜色理解状态 |
| 字体 | 中文系统字体栈；安卓遵循平台字体缩放 | 网页正文建议14–16px，长文16px；后台标签/元数据不得为密度无限缩小 |
| 间距 | 4/8/12/16/24/32/48基础级别 | 允许有依据的例外，不在页面随机加值 |
| 圆角 | 输入/按钮8px、面板12px、弹层16px建议值 | 录音主按钮可有独立形状，但状态和触控规则一致 |
| 触控 | 平板关键动作建议至少56dp触控区域 | 实机验证手指误触、横竖屏与大字体；尺寸不是收音或可用性实测 |
| 层级 | 页面、侧栏、抽屉、弹窗、提示的固定顺序 | 不用任意极大层级解决遮挡；弹层必须可关闭和恢复焦点 |

设计变量至少包含color/text/space/radius/type/motion层；组件使用语义名如text.primary、status.warning，而非每页直接写色号。后续品牌调整集中变更。首期不默认增加深色主题。

## 3. 基础组件及必须演示的状态

| 组件 | 必须覆盖的状态 | 行为 |
| --- | --- | --- |
| Button | 普通、焦点、按下、禁用、提交中、危险 | 提交中防重复；禁用给可理解原因；不能靠禁用实现后端权限 |
| Field/Select | 空、已填、必填、错误、只读、禁用、异步候选失败 | 标签不只靠placeholder；错误贴近字段，提交后聚焦首个错误 |
| Table/List | 加载、有数据、空、无匹配、失败、分页、部分刷新 | 区分首次空和筛选空；失败不伪装无数据；排序和页码可恢复 |
| Dialog/Drawer | 查看、编辑、预览、提交失败、版本冲突 | 焦点约束、Esc/返回处理、关闭后焦点回原入口；脏表单不能静默丢弃 |
| Toast/Banner | 短反馈、持续阻断、可恢复告警 | 关键失败保留在页面，不只靠几秒消失的toast |
| Status/Progress | 未开始、处理中、完成、受阻、失败、不确定 | 文字取STATE-01；传输100%后仍可能校验中 |
| PermissionBoundary | 未登录、无权、已撤销、会话过期 | 无权不出现会议标题/计数；技术故障不可显示为“没有权限” |

## 4. 业务组件目录

| 组件 | 输入与输出 | 特别规则 |
| --- | --- | --- |
| RecordingControls | 采集状态/实际时长/输入活动→开始暂停结束命令 | 开始是人工可见动作；是否长按结束仍为原型建议，待录音页签核 |
| RecordingOutcome | 本地保存/上传/处理/分发独立状态 | 不使用单个成功布尔值覆盖四段状态 |
| TranscriptPanel | 版本、段落、时间位置、说话人显示映射 | 长文分段渲染；证据跳转保留版本；未知说话人不补实名 |
| AudioEvidencePlayer | 授权资产、时间轴映射、播放状态 | 暂停/缺口位置映射准确；无音频/无权/链接过期分别反馈 |
| VersionEditor | 基础版本、内容、修改理由→新版本请求 | 保存不发布；冲突提供对照/重载，不覆盖机器原稿 |
| RoleScopeEditor | 主体、角色、范围、时间/历史边界、原因 | 一条授权整体预览；不把不同授权的功能和范围拼接 |
| DistributionPreview | 内容版本、目标、审核、受众、策略解释 | 预览无外发；版本/目标变化后要求重新核对 |
| RecoveryAction | 失败类型、影响范围、允许操作、原因 | 不提供跨失败类型的一键强制成功 |

## 5. 页面布局和导航

后台使用导航＋主工作区；组织页为树＋详情；会议详情为资料主区＋必要状态侧栏。一个路由完成一个主要任务，避免把所有管理功能堆成长页。桌面表格密度以连续操作可读为准，不为了装饰增加大卡片。

建议验证宽度：1600、1280、960、390像素；平板另按实际dp和设备方向验证。窄屏表格可在自身容器横向滚动，页面不可被表格撑宽；主要操作不能只出现在悬停状态。企业微信内详情适合单栏阅读，管理后台复杂编辑可优先桌面但需要明确移动边界。

## 6. 交互约定

保存草稿、审核通过、发布群摘要分别命名并给出结果；确认弹窗只用于危险、扩大访问或不可撤销后果，普通搜索/筛选不弹确认。新建/修改有必填错误时保留已输入内容；网络错误允许原样重试但需幂等与版本检查。

会话过期：停止新受控请求，清理敏感服务缓存；未保存草稿的短暂内存保留由T-03/T-07设计评审，默认不写浏览器持久存储；重新登录同一用户且仍有权后才能恢复。切换用户必须清除前一人的草稿、播放器和缓存。

加载、空、错误、无权四类状态都有可行动文案。文案说明“发生什么、资料是否保住、下一步谁能做什么”，不暴露后台堆栈和密钥。动画尊重减少动态效果设置，录音状态不能仅靠闪烁。

## 7. 交付与验收

交付：语义设计变量、可运行组件与状态展示页、组件API/交互说明、三个代表页面（录音、会议详情、用户权限）和视觉基线。技术组件库在T-02/T-03确定，现阶段不宣称已经选择或实现。

验证：键盘全路径、焦点恢复、触控、大字体、长中文/长名称、空/错误/撤权、四种屏宽、对比度测量、原生与Web语义一致。截图覆盖状态而非仅首页。设计系统新增组件必须先查现有目录，再复用或明确新增原因。

维护：业务状态改动先更新STATE-01；设计变量变更跑代表页视觉回归；组件行为变更关联受影响PRD/页面；不将业务权限写死在视觉组件里。

# PRD-00｜产品总纲与范围

版本：1.2-draft｜日期：2026-09-20｜状态：评审稿｜产品负责人：Alec｜适用发布：首期内部试点

## 1. 产品定位

建设一套公司内部的会议室录音与会议记录系统。固定安卓平板负责采集中文会议；普通使用者只需开始、结束录音。系统自动保存并上传，生成逐字稿、纪要和行动事项，再按已配置规则向企业微信发送摘要和完整记录入口。授权用户能核对原音频、修订内容，管理员能定位并恢复异常。

首期为一间会议室、通常五人。五人是目标测试场景，不是五个实名声纹账号或硬编码的说话人数上限。一间是首期部署规模，不应把 room_id、群地址或设备身份写死。终端已经确定为安卓平板；无需采购 Wave、配置其 MQTT 或实现其厂家 API 才能启动开发。

## 2. 依据与文档效力

来源 U-01 至 U-08 是本次对话中用户明确回答，见 BASE-01。除这些已确认目标外，本套具体页面、权限、状态和验收行为均为本次提出的可评审设计，不冒充用户逐条批准。参考资料 EXT-* 仅用于核实平台能力，HIST-01 为历史 Wave 协议，不是安卓首版规范。

本包是产品与验收文件，不是已实现的软件、测试报告或生产上线授权。可以在隔离环境使用合成数据开展原型和开发。正式业务录音、外部 AI、真实群推送、数据删除及上线，需要对应门禁批准；“需求已写入”不等于已经获得这些权限。

## 3. 首期目标与不变原则

目标 G-01：普通会议结束后，无需人员补点上传、生成、导出、转发。

目标 G-02：产生四类可关联资料：原始录音、带时间位置的逐字稿、会议纪要、行动事项。信息未明确时如实留空或待确认，不追求表面完整。

目标 G-03：可靠保存先于 AI 和通知。后台故障不能被伪装成会议成功；无法恢复的录音缺口必须可见。

目标 G-04：会议数据访问与群分发受控。公用平板录音权限不等于查阅全部历史；设备管理员也不天然拥有全部内容。

目标 G-05：实现与验证分层。模拟数据、模拟器、外部服务、真机和会议室试点分别留证，不相互替代。

## 4. 已确认范围

| 维度 | 已确认内容 | 约束说明 |
| --- | --- | --- |
| 规模与语言 | 一间、通常五人、中文 | 先验证这一场景，不承诺所有房型或方言 |
| 终端 | 自身联网的安卓平板 | 不依赖员工手机中转；后台服务器仍需要部署 |

| 使用对象 | 本公司内部 | 无外部客户、多租户收费或应用商店运营要求 |

## 5. 首期完整范围与开发顺序

P0 是首期试点必须具备的能力，不表示一个工作包同时完成。包括录音与本地保护、自动上传、完整归档、四类资料、修订与追溯、用户与组织管理、可配置角色、访问组和对象访问、有限配置的分发模式、设备配置、异常任务、审计和备份恢复。门禁按 DEL-01 分阶段推进。

P1 是明确可后置的增强：更多平板型号、企业微信单点登录、正式设备锁定/集中管理、批量导出、跨会议行动事项看板。它们不得成为核心流程能否开发的前置条件。

排除项：实时监听和字幕、视频与屏幕采集、远程无提示启动麦克风、声纹实名识别、会议预约、自动考核、自动催办、外部商业售卖、多公司租户、强制 Wave 兼容、必须复用某一个开源项目。未经变更审批不扩入。

## 6. 用户角色与体验

会议操作人员：无须输入个人密码即可在已配置终端录音；能看当前状态和必要故障，不可浏览前一场的标题、正文和音频。匿名操作只能审计到设备和会话，不能伪称已识别操作者。

记录用户：登录后只查看授权范围，可搜索、回听与查看对应版本。业务审核人可在授权会议上修订、审核和分发。平台管理员维护设备、账号、连接、任务，不默认读正文。角色能由同一人兼任，但要显式分配。

## 7. 标准流程与异常分支

标准流程：设备就绪 → 使用者开始 → 本地录制 → 使用者结束 → 本地封存 → 自动上传及服务端校验 → 转写 → 纪要/行动事项 → 按规则审核或自动分发 → 授权用户查看。

断网分支：有效的离线设备配置和足够空间下继续采集；结束后待上传，恢复网络自动排队。配置已失效则禁止新录音，但不能删除已有原件。

失败分支：原件已归档但 AI 失败时只重试处理；上传冲突、疑似录音缺口或发送结果不确定进入明确状态。没有规则只归档等待配置，不猜群；保密会议优先禁发。

## 8. 成功标准

在批准的五人中文实机场景中，正常会议仅需开始/结束；原音频可回放，全文、纪要、事项可核对；被授权且未参会的管理者能实际打开链接。断网与服务重启测试能按规则恢复；重复事件不重复建会；无权请求不得泄露元数据。

质量与速度采用 ACC-01 的统一样本和测量方法。具体最大会议时长、AI 阈值、容量与恢复目标须在正式试点前批准，不能以任意“99%准确”代替。

详细需求以对应 REQ 编号为准；公共规则只在规则文档定义。出现冲突时记录到 BASE-01，不以文件时间或代码现状擅自决定。签核方式见 DEL-03。

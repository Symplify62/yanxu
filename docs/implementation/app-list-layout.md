# App 公共记录布局修正

用户截图要求：去掉重复“公共记录”标题区，搜索/筛选区固定且更薄。范围为已确认A风格下的App嵌入列表、列表工具栏与对应设计规范；独立网页保留必要标题，录音与后端流程不变。

## 改前诊断与验证合同

- 文案规范已有“控件已表达的信息不重复”，因此重复标题也属于实现未执行既有原则；布局规范未明确原生导航与WebView标题职责、工具栏尺寸、滚动容器与吸顶位置，属于规范缺口。原公共列表直接复用独立网页页头及间距。
- App原生导航已表达“公共记录”，嵌入网页移除可见h1与其占位，保留可访问的区域名称；原生公共记录导航下留白收敛，网页不叠加独立站点顶部间距。
- 筛选与搜索两行固定在WebView可视区顶部；记录数放搜索行，不另占一行。标准字号下移动端工具栏目标约100 CSS px，按钮触控高度至少44 px、搜索框40 px；放大文字允许增高，不截字或挤成难点击的小控件。
- 内容列表滚动时工具栏位置不变，背景不透明、不遮挡首条/最后一条。搜索、筛选、清除和进入详情保持原行为。
- 验证：真实组件浏览器测试320/390/768/1280宽度、长列表滚动、空结果/清除、独立网页标题、加载状态；现有公共链路回归。Android模拟器截图检查原生导航与WebView实际衔接，发布前构建/类型/文档链接检查。
- 可见UI变更：涉及。已有工作区改动保留；不自动提交。

## 结果

- App嵌入列表删除重复h1与占位，保留区域名称；独立网页保留标题。公共记录导航下原生24dp空白移除，WebView左右8px、顶部0；工具栏吸顶且有不透明底色，记录数并入搜索尾部。
- 标准移动宽度下工具栏约102 CSS px，筛选触控高度44px、输入框40px；280px窄WebView将字体放大至20px时自动换行并增高，页面不被撑宽。320/390/768/1280宽度均验证滚动前后工具栏顶边不变。
- 新增6项布局/状态检查与既有1项真实服务完整流程，在本地与公网均通过。长列表与大字体使用测试响应，不修改线上记录；模拟器使用原有本地测试记录，验证真实App壳与WebView组合及滚动。后端22项回归、构建/类型、文档链接与diff检查通过。
- Android测试版0.1.5已更新到用户截图对应模拟器（emulator-5560），保持其原本的本地服务地址；公网安装包也已更新并核对SHA；确认物理手机未运行录音服务后，同步覆盖安装0.1.5，未清空其录音或设置。模拟器截图：`.local-data/deploy/list-after.png`与`list-scrolled.png`；快速录音页截图`record-layout-regression.png`确认共享布局未改变其他入口。
- 发现并修复网页缓存导致升级后仍显示旧布局：App每次版本升级首次进入网页清理资源缓存，入口HTML返回no-cache以重新校验；手机原音与记录文件不清理。
- 首轮公网布局检查失败：Nginx把HTTP/2静态资源并发请求算入20连接上限，部分CSS被拦截；服务器错误日志确认原因。现静态资源由Nginx直接提供并按内容哈希缓存，接口仍有限流与并发保护；重新执行同组公网测试全部通过。[Nginx计数说明](https://nginx.org/en/docs/http/ngx_http_limit_conn_module.html)
- 公网静态文件保留旧hash文件，入口HTML原子替换；仅重启API以应用缓存响应头，没有改动数据库/转写任务。回退备份在`/opt/yanxu/ui-backups/20260921-list`，包含此前HTML/API/APK/Nginx配置。部署模板同步在`deploy/nginx-https.conf`。
- 本轮没有提交Git。规范来源为02布局与03组件模式，页面规格只链接此记录，避免把细节重复堆入AGENTS。

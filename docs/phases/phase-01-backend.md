# 第一阶段后端与真实接入准备

状态：实施建议与检查点，未实现、未冻结具体框架/供应商/部署平台。2026-09-21用户认可当前原型方向，询问后端及其他考虑。阶段范围以[phase-01](phase-01.md)为准，页面以[页面规格](phase-01-pages.md)为基线。

## 1. 推荐形态

一个模块化API服务＋独立后台处理进程＋持久数据库＋音频文件存储。按模块组织，不把身份/组织/角色/发群带入本期。不要求先拆微服务或引入多种中间件。

候选数据库可采用PostgreSQL，任务先用数据库持久化领取、租约和重试；API和worker可共用一套代码、分别启动。文件开发期可用持久目录，公网部署选择持久卷或对象存储，不依赖进程临时目录。具体语言/框架在实施时按部署条件选择，与现有TypeScript类型/契约协调。

PostgreSQL官方说明SKIP LOCKED可用于多消费者访问队列表的锁竞争场景；这支持数据库任务表候选，但不能替代租约、幂等、超时、崩溃恢复的实现与测试。[官方文档](https://www.postgresql.org/docs/current/sql-select.html)

## 2. 本期模块与职责

| 模块 | 必須完成 |
| --- | --- |
| 录音接收 | 创建稳定录音ID；接收/校验音频或分片；结束封存；重复请求返回同一记录；缺片不报完整 |
| 记录与资产 | 记录元数据、音频引用/校验信息、时间/时长；原音频与文字结果分开保存 |
| 处理任务 | 持久状态、领取/超时、重试、阶段恢复；进程重启后可续作，关闭前端不停止已接收任务 |
| 转写适配 | 处理格式/大小/时长限制；保存真实逐字稿及可用时间戳；长录音分段后校验覆盖与顺序 |
| AI分析适配 | 基于实际内容生成摘要、重点、决定、事项；结构校验、依据关联、未知信息保留；记录用量 |
| 公共查询 | 匿名列表、分页/搜索、详情与阶段状态；产物分步就绪；不返回内部存储路径/密钥 |
| 运行支持 | 日志、健康检查、失败任务诊断、预算/并发限制、数据库/文件备份恢复 |

公开查看不附加员工身份；录音ID/上传会话只是标识和去重手段，不是用户登录。公开接口本期不提供任意编辑/删除或运维恢复能力。

## 3. 数据与接口边界

核心数据先围绕Recording、AudioAsset/UploadPart、ProcessingJob/Attempt、Transcript/Segment、AnalysisResult/ActionItem组织。避免先建完整User/Department/Role/Distribution模型作为前置。

接口需覆盖：创建录音/上传会话、写入分片或文件、查询上传状态、封存结束、分页公共列表、单条详情与处理状态。具体路径、字段、错误码在实现前形成契约；当前旧mock接口不是已验收的生产契约。

原音频先可靠落盘/入对象存储并校验，再以事务确认资产记录和待处理任务。存储成功但数据库失败、响应丢失重试等情况必须能对账/补齐，不能重复创建同一录音。用户点击“结束”与“服务器完整接收”是不同时间点；页面只显示实际到达的状态。

## 4. 自动处理规则

目标阶段：本地保存/上传 → 服务器校验完成 → 等待转写 → 转写就绪 → 等待分析 → 分析就绪。失败记录具体阶段与下一次重试；已完成的转写不因分析失败重复跑。

短暂网络/限流错误可退避重试；格式损坏、凭证/额度配置错误不能无限重试。外部请求超时结果不明时保存外部任务ID并先查询状态，供应商支持幂等时使用幂等键；不能承诺所有供应商均可完全避免重复计费。

长录音按供应商限制分段、保留顺序和时间映射；总结覆盖全部分段，不能只取开头。AI输出需验证结构，失败保留原始响应供受控诊断，不把空/错误输出当正常摘要。会议内容作为不可信数据，不作为改变系统流程的指令；页面以安全文本/受限格式显示。

## 5. 后端之外的必要工作

### 真实采音与设备

当前按钮只演示状态，仍需真正接入麦克风、停止事件、片段保存/上传及异常反馈。公开网页采音使用HTTPS并获得用户麦克风许可；本机localhost测试与公网HTTP不同。[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)

需要用目标设备验证长录音、暂停、锁屏、切后台、麦克风被占用/断开和断网。MediaRecorder分片间隔并不保证精确，Safari暂停麦克风或Android Chrome锁屏等行为可能延迟数据事件、产生大块数据；不能用块数计算准确录音时长，也不能把任意Blob块当独立可识别音频。[MDN dataavailable](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/dataavailable_event)

“不设业务时长截止”继续保留；设备空间、浏览器缓冲与供应商限制要实际处理。采集中断/页面被系统关闭与服务端任务重启恢复是不同问题，分别验收。

### 公网与资源控制

匿名读已确认；匿名上传与模型调用仍需请求校验、并发/速率限制、用量记录和预算上限，避免公开接口产生无限资源消耗。供应商密钥只留服务端。域名/HTTPS、网络和存储部署落实后，才能进行不同网络/设备的公共访问验收。

原始音频默认保存，不自动等同于公开试听/下载；如需加入公开回听，应明确该资料的公开范围。公开结果不意味着源目录、旧原型、日志和运维接口也对外可见。

### 数据与维护

延续长期保留方向，落实容量监测、数据库和音频共同备份以及恢复测试；本期不做公开删除入口。部署升级要能恢复未完成任务；记录版本/供应商配置，用于重现问题。少量运行诊断可先用受控日志或命令，不必先搭管理员界面。

## 6. 实施次序与验收

1. 真实录音＋可靠保存＋记录查询：拿到可核对的实际音频，刷新/服务器重启不丢已确认记录，重复上传不重复建档。
2. 接入转写＋AI分析：一份真实样本自动产出对应文字和分析；验证长录音覆盖、错误恢复与用量。
3. 公共结果联调＋公网验证：替换页面演示数据，另一网络/设备不登录可见同一结果；完成HTTPS、备份、资源限制和诊断验证。

供应商未配置时可以做可替换接口与测试替身，但真实转写/分析验收仍保持未通过；不能再把固定样例算第一阶段完成。

## 7. 待落实的少数外部条件

- 目标录音设备/浏览器，或是否必须原生端；用户已先确认页面，没有同时确认原生采集路线。
- 转写与AI服务的可用账号/模型及费用范围；允许外部能力的既有方向保留，不猜实际凭证。
- 公网部署位置、域名与HTTPS条件。
- 如本期要求公开原音回听/下载，需要明确这项范围；当前公共结果优先是文字与分析。

数据表、接口拆分、任务领取与恢复、测试自动化等常规工程细节由开发调查落实，不要求用户逐项决定。

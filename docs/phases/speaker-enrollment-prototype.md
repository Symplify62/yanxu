# 录音、个人配置与管理后台：声音档案交互原型

状态：2026-09-22 第二版交互原型，按用户要求重做，待用户体验确认。用户否定首版以成员列表作为会前主页面的形式，要求录音页直接头像点选，正式操作与配置分离，后台至少用户、角色、部门、声纹管理。

## 三类入口

| 入口 | 核心任务 | 原型路由 |
| --- | --- | --- |
| 正式操作 | 录音页点头像选人，开始/暂停/结束；自动生成并查看逐字稿/纪要 | `speaker-prototype.html#/record`、`#/records` |
| 个人与设备设置 | 本人声音档案、麦克风/品质演示配置、记住本场成员 | `#/settings` |
| 管理后台 | 独立侧栏，单次只呈现一个管理工作区 | `#/admin/users`、`#/admin/roles`、`#/admin/departments`、`#/admin/voices` |

录音页没有管理表格。常用人员用头像/姓名元素直接多选，头像描边和勾选表示本场已选，独立文字表示声纹状态。更多人员在可搜索、按部门筛选的头像网格抽屉中选择，找不到的人可以就地添加临时来宾。后台保留表格、角色权限表单与部门树，针对维护任务使用不同密度。

## 正式操作

1. 打开就是录音页，主区为计时、波形、开始按钮；会议名称可直接编辑。
2. 点头像加入/移出本场，至少选一人。选人不是身份认证，头像不会模拟实时发言人识别。
3. 未就绪声纹可就地逐人录入：明确本人→示例采集→试听→确认姓名→本人确认声音；长期保存另有同意。修改姓名后原确认失效，重新录入取消保留旧档案。
4. 保存后展示“生成中”，之后模拟转为“可用”；不是录了一段音就直接表示真实可识别。
5. 声纹未就绪时可明确选择继续，演示逐字稿对应人员显示说话人编号。声音和姓名正确性不是本轮验收内容。
6. 录音中可以加入迟到人员；已在本场的人不允许在录音中删除，避免抹掉前段发言归属。配置与后台导航在录音/处理中锁定。
7. 结束自动整理，无额外发布确认；演示结果存入会议记录。历史记录使用独立快照，不因成员改名或停用而改写。

## 全选行为

录音页“全选当前人员”只作用于当前展示头像；更多人员“全选筛选结果”只作用于当前搜索与部门筛选结果，取消时保留筛选外已选人员。部分选择显示半选，无结果或无录音权限禁用。录音/暂停期间仅可批量追加，不能批量删除已入场人员，不重复加入。

真实名单快照、身份与声纹处理的落地见[后端实施设计](speaker-backend-design.md)，属于待实施方案。

## 每个人的声纹录制入口

录音页常用头像与“更多人员”头像网格中，每个人都有独立按钮：未录入、撤回、需重录显示“录制声纹”，已有可用档案显示“重录声纹”，生成中禁用。头像本身只负责选入/移出本场，录制按钮不会改变参会名单，不要求先选中此人。

从更多人员进入录入弹层时，保留抽屉、搜索和部门筛选。保存或取消后回到原处；不自动开始其他人的录制。临时来宾同样提供入口，仍只用于本场。

会议组织者可以协助任意可选人员录入，仍须本人确认姓名/声音及长期保存同意；不因此获得后台删除权限。普通成员仅维护本人，声纹管理员仍可维护档案。主会议录音、暂停或整理期间保留入口但禁用，并显示“会后录制”，避免主录音与登记声音混用。

## 管理交互

| 模块 | 可操作内容 | 约束 |
| --- | --- | --- |
| 用户 | 新增、编辑姓名/备注/部门/角色、停用/启用、筛选 | 同名同部门同备注拦截；停用不出现在新会议候选；示例管理员不能停用 |
| 角色 | 新建、编辑操作权限、删除未被引用的自定义角色 | 内置管理员只读；被成员使用的角色与内置角色不能删除 |
| 部门 | 树形选择、新增子部门、编辑名称/上级、删除空部门、查看直属成员 | 根部门保留；禁止循环层级；含成员或子部门时先迁移才能删除 |
| 声纹 | 状态筛选、详情/合成试听、录入/更新、标记需重录、撤回 | 未录入/生成中/可用/需重录/已撤回分开；撤回后不用于新会议，用户和历史结果保留 |

顶部“演示身份”属于原型评审工具，可切换管理员、会议组织者和普通成员。操作权限会联动后台入口与本地操作方法，直达无权限路由显示无权限。它不代表正式登录/后端鉴权，不能作为生产安全机制。

个人设置只维护当前演示身份的声音；正式授权、组织数据范围和真实声纹生命周期仍待实现。来宾不自动创建登录账号，不进入长期成员库；组织管理员可另行通过用户管理建立正式成员。

## 正式登录方向

2026-09-22 用户确认后端第一版由组织者和管理员使用账号密码登录；参会同事只需被选入名单，不必逐人登录。当前顶部身份切换仍为原型演示，并未接真实账号。

## 工程与运行

沿用Vue、Element Plus和A方案。保持当前功能分支，旧原型已备份到本机忽略目录。第一阶段真实Web/API和Android无改动。

在 frontend 执行 `npm run dev:speakers`，打开 `http://127.0.0.1:5180/speaker-prototype.html#/record`。独立 `npm run build:speakers` 输出到 `.local-data/speaker-prototype-dist/`，不进入正常公网构建。

- [页面入口](../../frontend/src/speaker-prototype/SpeakerPrototype.vue)只协调路由/弹层。
- [录音页面](../../frontend/src/speaker-prototype/RecorderSurface.vue)、[头像选择](../../frontend/src/speaker-prototype/PeoplePicker.vue)、[后台](../../frontend/src/speaker-prototype/AdminWorkspace.vue)、[设置](../../frontend/src/speaker-prototype/SettingsPage.vue)独立组件。
- [状态模型](../../frontend/src/speaker-prototype/model.ts)维护稳定ID与引用、持久演示数据和权限演示。
- v2独立localStorage键 `yanxu-speaker-prototype-v2` 保存成员/角色/部门/演示配置/历史；sessionStorage保留本场名单和演示身份。不会覆盖v1数据或其他站点数据。
- 本轮不启用麦克风、不读取实际设备列表、不发送API或声音；合成音频用于试听。刷新正在录音时只恢复准备名单，不冒充原生可靠录音。

## 正式实现仍需落实

组织者登录/设备授权、员工与外部人员账户关系、管理操作与数据可见范围；本人声纹同意/撤回、原始样本与特征的保留/删除政策；真实采集质量、模型准确率、跨设备/跨会议匹配、长会议与失败恢复；实名结果公开范围。历史快照中的发言归属与长期可识别声纹是不同资料，不能把撤回未来识别等同删除历史发言。

## 验证入口

[定向交互测试](../../frontend/tests/speaker-prototype/enrollment.spec.ts)使用仓库Playwright，覆盖录音头像选择、声音确认、管理联动、演示权限、配置和三档布局。运行 `npx playwright test -c playwright.speakers.config.ts`。

本轮约定、原始日志、390/768/1280截图及最终结论位于 `.local-data/evidence/speaker-redesign/`。这些证据证明可点击原型行为与布局，不证明真实身份认证、声纹识别效果或生产发布。

# 用户体系、会议名单与声纹识别：后端实施设计

状态：2026-09-22 可评审建议；依据当前源码核查与第二版原型。全选及声纹入口已在原型演示，本文件不表示真实后端已实现、迁移或发布。

## 1. 推荐形态

沿用阿里云上的 FastAPI API/主库、七牛对象存储、Mac 主动领取音频任务和 DeepSeek 文本分析。先做单组织的模块化服务，现有 SQLite WAL 在当前单主实例阶段继续使用；多实例或实测并发压力出现后再评估 PostgreSQL，不为本需求先拆微服务。

新增能力分为：身份与权限、人员目录、声音档案、会议参会快照、说话人区分与姓名关联。声音样本与提取特征从开始就按私有资料处理，与已允许公开的会议原音分开。

当前已确认的产品方向：头像点选/按筛选全选；每个人独立声音入口；录入前后确认姓名及本人声音；已有声音跨会议复用；后台含用户/角色/部门/声纹；结束会议后自动处理。用户已确认第一版由组织者和管理员使用账号密码登录，参会同事不必逐人登录；新增实名公开范围尚待确认。原型身份切换器不替代正式鉴权。

## 3. 对象分工

| 对象 | 最小职责与关键约束 |
| --- | --- |
| Person | 稳定人员ID、姓名、头像、部门、备注、内部/外部类型、启停状态；不以姓名做主键 |
| Account / Session | 登录主体、Person关联、凭据/会话状态、注销/失效；来宾不必拥有账号 |
| Department | 父部门、名称；禁止循环；有成员或子部门不能直接删除 |
| Role / Permission / AccountRole | 操作权限与分配关系；用户停用和权限变更由服务端实时校验；受引用角色不能硬删 |
| VoiceEnrollment | 一次登记尝试、目标Person、操作者、本人确认/长期保存同意、样本资产、提交状态、幂等键 |
| VoiceProfileVersion | 登记来源、模型/特征版本、质量结果、状态、active指针、授权revision；特征不发前端 |
| MeetingSession | 会前会话/clientSessionId、组织者或授权设备、开始时间、名单revision；与上传录音记录关联 |
| ParticipantSnapshot / Event | 本场稳定PersonID或guestID、当时姓名、允许使用的声纹版本、加入的音频时间点；追加事件幂等 |
| SpeakerAttribution | 本场匿名speakerId、发言时段、匹配personId或unknown、质量/证据、模型与输入指纹、结果版本 |
| VoiceJob / Attempt | enrollment生成或recording归属任务、租约、尝试次数、输入revision、下一次重试、失败阶段 |
| AuditEvent | 用户/角色/部门变更、登记/使用/撤回声音的责任人与对象；不记录原始特征或密钥 |

保留同一条纯ASR逐字稿，身份归属单独成结果版本。正式历史文本使用当时姓名快照，改成员姓名不直接重写历史。来宾的长期身份档案和本场记录分开：会议可以留存已授权的历史发言标签，不代表继续保存其可用于未来认人的特征。

新增表使用外键/唯一键及事务约束，并检查当前SQLite连接是否启用外键。ID/revision与角色检查是服务器职责，不相信客户端传来的声纹状态或管理员标识。

## 4. 全选如何接后端

- 原型首页“全选当前人员”作用于下方展示的头像；更多人员“全选筛选结果”作用于当前部门＋搜索结果。取消仅移除同一集合，保留过滤外已选；声纹未录入不影响名单勾选。
- API提交明确去重的personIds，不提交一个长期生效的selectAll=true规则。服务端校验人员存在、启用、组织者有权选择，再保存名单快照。
- 正式目录有分页时，必须区分“全选已加载”与“全选全部筛选结果”。如需跨页全选，增加受授权的选择解析接口，返回固定ID集/数量/revision/过期时间供确认；新建人员不悄悄进入已确认集合。
- 会前线上创建MeetingSession；开始实际采集时，本机同步落盘clientSessionId、名单快照及事件。最终录音文件具备大小/SHA后，再用现有上传链路扩展关联这个会话。
- 最终上传创建携带meetingSessionId和finalRosterRevision；服务端校验会话属于当前组织者、追加事件已同步，并在封存前原子冻结最终名单与指纹。封存/处理后禁止追加；首版会话与最终录音记录一对一（内部上传可分片），唯一约束保证重试返回同一关联。
- 离线已缓存人员的录音先可靠保存，恢复网络后上传同一名单；新身份授权过期或权限已撤回时，明确拒绝相应发布/匹配并保留本机音频，不假成功也不删除录音。首次离线登记及新来宾同步策略待定。
- 录音中只追加迟到者，不允许取消已加入人员来抹去前段归属；请求以eventId和expectedRevision幂等/防并发覆盖。加入时间使用累计采集时长；[Android暂停时不写音频](../../android/app/src/main/java/cn/jiajian/yanxu/RecordingService.java)，不能直接使用墙钟计时。
- 老客户端无名单时继续提供普通转写，speaker未知；不能凭声音或历史名单猜出实名。新增参会人员或会议会话字段必须走已认证、已授权的路径；匿名旧协议遇到这些字段明确拒绝，不能忽略后偷偷生成受保护关系。新协议幂等键按组织者/授权设备命名空间校验，返回既有上传凭据之前还要验证归属；不能仅凭client_id及文件SHA/大小取回其他人的上传token。兼容旧纯音频请求不代表允许匿名调用者引用受限名单或声纹。

| 样本上传与确认 | enrollment专用上传会话、complete、confirm | 私有资产、文件校验、本人姓名/声音确认、长期授权；服务端校验提交完整性 |

| 录音中追加 | POST /api/meeting-sessions/{id}/participant-events | append-only、eventId去重、音频时间点，拒绝过期名单覆盖 |
| 录音上传 | 扩展现有创建/分片/complete契约 | 关联会议会话；同client_id但音频或名单冲突返回409，不静默替换 |
| Mac任务 | /internal/voice-jobs的claim/heartbeat/complete/fail | 分用途机器凭据、租约owner、job输入版本、私有资产短期授权 |

接口统一明确401未认证、403无权、409版本/幂等冲突、422内容不合法与可恢复失败。权限和字段验证在服务端实施，不由前端隐藏按钮代替。

## 6. 声音登记与会议处理

### 登记生命周期

创建登记 → 私有样本上传且校验完成 → 本人确认姓名/样本/保存范围 → 质量检查 → 特征生成 → 候选版本可用 → 事务切换active版本。

参会者不登录时，首版确认是本人在组织者设备上现场完成。记录组织者、目标人员、确认方式、时间、样本哈希/版本和保存范围；这是一份现场确认记录，不等于账号认证或身份核验。服务端校验协助权限与记录完整性，不因confirmed=true就宣称已验证本人身份。

- 质量检查包含有效语音、噪音/重叠/多人混入等，不能只按录音秒数通过。
- 候选版本生成失败或用户取消时，旧active版本继续有效。界面应分别显示“原档案可用”和“本次更新失败”，不误清空。
- 同一人并发登记使用revision条件更新，晚到任务不能覆盖更新版本或撤回。
- 撤回立即禁止未来识别，并使在途任务提交前再次校验授权revision；撤回后到达的旧结果不能重新启用声纹或发布新的实名归属。
- 服务端样本、特征、Mac缓存、对象存储与备份恢复均需清理/撤回标记；旧备份恢复不应重新激活已撤回授权。保留周期由产品政策确认。

### 会议生命周期

原音可靠封存 → Qwen转写/对齐 + 说话人分段 → 根据本场候选与有效profile版本匹配 → 归属结果校验 → DeepSeek根据带依据的逐字稿整理 → 自动提供结果。

- 分段/聚类编号是本场内部speakerId，真实姓名是另一步有证据的关联；同名、未知来宾、重叠和低可信度都不能强制分配给名单中的人。
- 本场名单是候选范围，不证明只有这些声音。缺席/未选中的旁观者应保留unknown，不就近错配。
- 长会跨音频分片维持稳定speakerId，原文segment IDs与时间映射可追溯。重叠时间可表达为多说话人/未知，不能用单标签掩盖无法区分的事实。
- 分人失败不使成功的ASR和原音丢失；可先显示普通逐字稿和明确的分人状态。恢复时只重跑失败阶段。
- DeepSeek只用文本和归属证据做纪要，不承担凭文本猜声音的任务；发言人不自动成为行动事项负责人。
- 若普通摘要已生成，之后归属就绪，生成受版本约束的新分析结果并控制重复计费；不重做已成功纯ASR。

### 缓存、任务和版本

新增声音任务使用独立voice_jobs与唯一(stage, subjectId, inputFingerprint)，沿用现有租约/心跳/过期回收/owner检查思路。不要破坏旧recording_id唯一的asr→analysis任务。

归属缓存指纹至少包含audio SHA、ASR结果版本、名单快照revision、所用profile版本集合、声纹/分段/对齐模型及参数版本、授权revision。姓名或声纹改变时不能只凭同一个音频SHA复用旧实名结果。DeepSeek现有transcript/model/prompt指纹可以扩展包含attribution结果版本。

提交阶段再次检查租约与输入/授权版本，幂等提交只产生一个有效结果。重试成功不重复发布、重复入账或覆盖更新结果。

## 7. 安全隔离与兼容

当前公开回听/下载的授权只涉及会议结果，不包含登记声音和声纹特征。声音样本用独立私有空间或等效私有资产层，不能进入现有拼接公开URL的逻辑；只给有权限的端点和领取该任务的worker短期访问。

后台账号、设备会话、上传会话、转写任务、私有声音任务、备份维护使用不同权限边界。特别是现有/internal/asr/backup与ASR共用凭据，应在新敏感表上线前拆分，旧备份作业需同步迁移。凭据与私有字段不进日志或公开DTO。

数据库迁移先在副本演练，保证旧App不传人员时仍可录音/上传/查看；正式启用受保护新入口分版本/开关推进，不将未知旧数据批量变成用户或声纹。应用回滚不能直接丢弃新表；保留向前兼容数据或明确维护窗口回退策略。

## 8. 建议实施顺序与每段完成条件

| 阶段 | 实施内容 | 可验收结果 |
| --- | --- | --- |
| A：基础与可行性并行 | 明确登录/公开范围；设计迁移及契约；在Mac上用同事样本验证分人+登记匹配 | 可评审数据/接口；真实误认、未知、耗时基线，决定模型与阈值，不用样例分数冒充实测 |
| B：目录与身份 | 最小登录、人员/账号分离、用户/角色/部门、受保护选人API | 前后台共享真实名单，直调越权失败；旧公开读回归通过 |
| C：真实登记 | Android专用采样/试听/确认、私有上传、生成、版本、重录/撤回 | 设备重启可恢复，原样本可校验；新登记失败不毁旧档案，撤回后旧任务提交被拒 |
| D：真实会议名单 | 会话创建、全选固定ID集、快照、来宾、迟到追加、断网重试 | 名单不随新用户/改名漂移；重复上传/追加不重复；暂停后的加入时间正确 |

| F：分批发布 | 迁移副本验证、鉴权/撤回并发/旧worker/缓存/长录音/公开字段测试 | 明确提交、部署版本、APK与回退步骤；源码/自动化/运行/业务验收分别记录 |

A的模型验证可以和B的基础开发并行，但真实声纹有效性应在承诺具名归属前完成。现有租约、上传、公开读和云对象校验测试继续复用，新建真实身份/声纹专项，不要求用户反复代做回归。

## 9. 待定事项与建议默认

- 登录方式（已确认）：组织者和管理员使用账号密码；参会人员和来宾不必有账号。首版不接企微/钉钉单点，不以共享设备授权替代组织者登录。实施包括安全密码哈希、管理员初始化/重置、会话失效/退出、登录尝试限制、账号停用即时生效；Web与Android凭据保管分别落实。默认不增加公开注册或要求逐位参会人登录。
- 实名公开：原音及既有文字已允许匿名访问；新增结构化实名归属、人员目录、声纹档案各自确认范围，不从原音公开推导全部公开。仅隐藏姓名标签也不等于原音已匿名化。
- 管理范围：首版可建议单组织，部门用于筛选，后台操作与资料可见范围分开；是否允许所有组织者协助全组织人员登记仍需正式规则。
- 声纹保留：样本/特征保留多久，撤回后历史发言标签如何处理，备份保留与恢复后的撤回策略。
- 离线：保留现有可靠录音目标；第一次无网络注册用户/声纹是否必须支持，需决定实现范围。

本轮没有运行迁移、建立真实账号、上传同事声音或调用模型。本文件是后续实施依据，用户确认/调整后再进入相应切片。

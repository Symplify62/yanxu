# DES-07｜后端模块与异步任务设计

版本1.3-draft；技术建议，未实现。业务状态以STATE-01为准；接口见DES-02，实体见DES-08，授权见DES-09。对应REQ-UPL、REQ-AI、REQ-DIST、REQ-SEC、REQ-NFR。

## 1. 模块和用例边界

建议首期采用模块化单体API＋可独立运行的worker＋关系型数据库＋私有资产存储。数据库任务表及事务事件作为首期候选；是否需单独消息中间件通过T-04决定，不作为当前规模默认前提。

| 模块 | 拥有的用例/数据 | 对其他模块的调用 |
| --- | --- | --- |
| Identity/Access | 会话、用户、组、角色、授权、委派 | 提供统一动作/对象判断；不读取正文来判断权限 |
| Device/Ingest | 配对、设备令牌、上传会话、分片校验、收据 | 检查设备范围；封存后发布归档事件 |
| Meeting/Content | 会议元数据、版本、来源证据、修订 | 私有资产读写；发布内容版本事件 |
| Processing | 转写/总结任务、模型/模板指纹、尝试与用量 | 外部调用前检查当前数据策略 |
| Distribution | 规则、自动快照、消息快照、目标、尝试 | 读取指定内容版本并发送前重新检查 |
| Administration | 配置、恢复、清理计划、诊断 | 调用业务用例，不直接改表绕过状态和授权 |
| Audit/Operations | 审计、关联标识、健康指标 | 不把全文或秘密作为普通日志载荷 |

HTTP控制器只做协议转换、身份读取和用例调用；业务判断集中在服务/use-case；数据库与存储通过边界接口调用。禁止多个页面或worker各写一份角色判断、发送或删除逻辑。

## 2. 文件与数据库的一致性

归档建议流程：

1. 认证设备，取得服务器认可的room与设备映射；设备提交的归属只作核对，不决定权限。
2. 按upload_id/asset_id/part_no写临时区，流式计算大小与摘要，拒绝异常路径/格式/资源消耗。临时写成功不返回最终归档成功。
3. 完成请求携带封存清单；验证所有分片和内容摘要、媒体可读性、时长与清单一致。已知缺口保持INCOMPLETE，不借拼接改为COMPLETE。
4. 将校验通过资产发布到私有不可变位置，再以数据库事务建立/更新会议资产映射、RECEIVED_VERIFIED收据、待处理事件和审计。数据库提交成功后才返回收据。
5. 存储已写但数据库失败：保留可识别的孤立资产并由同幂等请求补齐；不得另建同场会议。对账任务区分仍有活跃上传、失败可恢复和过期临时片段。清理只针对已证明非唯一原件的临时副本。
6. 数据库已提交但响应丢失：查询或重放同请求返回原收据。读回音频并核对摘要属于归档测试；备份成功另记，不隐含在收据中。

存储和数据库没有一个天然跨系统事务，测试必须在每个边界终止进程。文件发布方式依T-04/05实际存储决定，不能只凭SDK返回值宣称永久保存。

## 3. 可靠事件与任务领取

事务内写业务结果和outbox事件（或等价可靠机制）。事件投递可重复，消费者按event_id与业务键去重；扫描未处理outbox可修复“归档有了但任务没启动”。

任务至少含kind、input_version/fingerprint、config_version、status、attempt_count、next_run_at、lease_owner、lease_until、lease_generation、cancel_requested、result_ref。业务任务唯一性建议为(kind, meeting_id, input_fingerprint, config_version, generation_request_id)；同任务重试不变generation_request_id，用户明确重新生成才新建。

领取通过数据库原子条件更新/锁定实现，不能先查询再无锁认领。worker获得有期限租约与递增generation；心跳延长租约。过期可重新领取，但旧worker结果提交必须匹配最新generation和输入版本，防止迟到结果覆盖新任务。任务租约时长、心跳间隔、并发和上限由T-04实验确定。

## 4. 按失败类型恢复

| 失败 | 状态/动作 | 禁止行为 |
| --- | --- | --- |
| 未提交外部前网络不可用 | RETRY_WAIT或等待网络；有界退避 | 快速无限请求 |
| 配置/授权缺失 | BLOCKED_CONFIG或AUTH_REQUIRED | 自动换云、换群或重新注册 |
| 输入非法/摘要冲突 | REJECTED/CONFLICT，隔离 | 用新内容覆盖旧资产 |
| AI可能执行但未拿到结果 | 尝试记录external_outcome=UNKNOWN；任务暂停自动重试等待查询/人工 | 不区分状态就重复付费 |
| 分发请求已提交，结果不明 | 分发任务UNKNOWN | worker崩溃后当普通失败重新发送 |
| 版本已变化 | 结果仅保存为原来源的历史产物；不得更新当前确认版本 | 静默覆盖人工修订 |
| 已撤权/删除/停发 | CANCELED/BLOCKED，记录原因 | 重试入口绕过当前约束 |

AI执行状态不明：沿用STATE-01处理状态集合，以FAILED加needs_reconciliation=true暂挂，尝试记录保留UNKNOWN；不新增与分发UNKNOWN混用的处理主状态。适配器若提供查询/幂等，按原external_request_id核实；否则由批准规则人工决定是否承担重复费用。

重试只重做失败阶段；总结失败不重跑已成功转写。指数退避、随机抖动、最大次数、最大累计时长可配置；正式取值依据服务限制和负载实测。超限进入人工处理，不删原件。

## 5. 并发、授权与取消

内容/配置/授权修改带expected_version；校验、写入、审计尽量处于同事务。预览只给影响说明，提交时重新算权限与版本，不能相信客户端提交的可授权清单。

系统自动任务使用受限服务身份和已启用配置，保留会议扫码发起人与冻结发布快照，不依赖员工仍登录或逐场人工审核。员工停用后不可登录查看；已录原件继续保全，外发执行前按当前数据范围和配置复核。

取消先写持久标记，在外部调用前和本地结果提交前检查。外部已收到的数据/消息不能保证被撤回，记录披露事实。长时间媒体响应只能阻止后续请求或切断未发送部分，不能抹除用户已缓存数据。

## 6. 删除、恢复与配置发布

删除先阻断访问和新任务，再清理资产/索引/导出，保留必要删除标记，备份恢复先应用标记。保留锁允许受控保存但不自动恢复常规访问。临时资产回收与业务原件删除是不同用例，分别审计。

配置采用草稿→校验→预演→发布新版本；回退也是新版本。正在录音继续使用采集快照；服务端停发/禁外部AI/撤权等收紧使用当前值。放宽规则默认不作用历史会议。

## 7. 验证与交付

交付模块边界、任务状态与业务唯一键、失败分类表、配置字典、日志/审计字段、恢复命令及接口契约。故障验证覆盖：重复事件、两worker抢任务、租约过期旧worker提交、文件写后数据库失败、提交后响应丢失、发布超时、删除后AI迟到、服务重启恢复。精确参数和值在T-04/05关闭后补齐，未关闭不能宣称无人值守达标。

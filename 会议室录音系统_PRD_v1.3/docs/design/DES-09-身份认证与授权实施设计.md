# DES-09｜身份认证与授权实施设计

版本1.3-draft；ACL-01和PRD-07为业务规则来源，本文是实施建议。账号来源D-06/D-16、历史边界D-18、委派责任D-19未确定，不以示例账号代替实际名单。

## 1. 三种身份分别处理

- 人：后台/手机登录，拥有账号、会话、角色范围及必要委派资格。
- 设备：一次性配对后取得最小设备凭证，只允许自身采集配置、上传和必要状态；不获取全公司记录。
- 服务：后台worker使用受限服务身份，记录来源任务和配置；不会因为是后台进程就跳过会议数据策略和外发约束。

首个管理员由部署时一次性受控初始化获得；无默认共享密码。该身份解决系统维护，不天然取得会议正文；业务授权资格由批准的初始化记录显式建立。最后可恢复管理员保护必须在事务里验证，普通页面不能绕过。

## 2. 用户认证方案草案

身份路线已确定为企业微信：有效本企业员工首次登录自动开户并采用组织信息；手机外网访问和每场平板扫码均需实际接入验证。T-07剩余任务是企业应用权限/回调、组织同步/离职停用、一次性挑战与会话设计，不再选择生产独立账号路线。

Web初始建议同源后台会话：安全、HttpOnly、合适SameSite策略的cookie，服务端控制过期与撤销；状态变更请求加入适合所选框架的CSRF/来源保护。登录回跳仅接受本站路径，登录成功轮换会话标识。部署跨域或统一身份重定向时重新评审cookie策略，不将建议参数不加验证复制到生产。

普通员工不另设系统密码；企业微信身份恢复遵循该身份源。本系统维护应急恢复资格需要明确人员与受控流程，不能作为免身份进入正文的后门。会话时长、组织同步时效和恢复责任在T-07/D-19记录。

外部身份以provider/issuer/external_subject关联，绑定需验证两端身份或受控管理流程；同名、同手机号显示或同邮箱文本不能自动合并账号。身份源故障不得自动降级成免登录。

## 3. 单次操作的授权顺序

1. 身份有效、账号/设备未停用、会话/凭证未撤销和未过期。
2. 对象存在且允许进入当前操作态；删除、受限等级、保留锁等约束先判断。
3. 找到当前主体及有效业务组来源的授权；角色、对象范围、有效期和历史边界在同一条授权内同时匹配。
4. 将完整满足条件的授权结果合并；不能用A授权的功能加B授权的范围。
5. 授权/角色/组维护另检查可委派资格和影响对象，不以“我能查看”推导“我能让任何人查看”。
6. 执行需要的版本检查和审计，修改在事务内提交；高风险审计失败不得无痕生效。

当前显式停用/撤销等否决约束优先。受限会议不继承普通部门全量范围。部门负责人的字段只描述组织关系，不自动转换权限。有效权限解释只对有资格的人开放，不能成为枚举秘密会议的接口。

## 4. 权限目录建议

功能码建议按语义命名：meeting.read、audio.play、audio.download、content.export、content.edit、distribution.recover、distribution.configure、user.manage、department.manage、role.manage、group.manage、grant.manage、device.manage、operation.recover、audit.read、retention.manage。

菜单和按钮是这些能力的显示结果，不作为安全边界。保护角色、具体授权范围和管理员委派规则在T-07冻结；原型只有部分业务权限勾选，不能视为完整目录实现。

权限矩阵至少逐一覆盖：列表/搜索/计数、详情、音频Range、下载、导出、正文修改、自动发送策略、异常恢复、配置、后台重试、恢复、删除。任何新增入口必须登记对应动作与对象范围。

## 5. 撤销、调岗与后台任务

停用账号：持久更新status/auth_version并撤销会话；下一受控请求拒绝。调岗和移组：撤销由旧关系产生的资格，保留合法独立授权，并向操作者解释来源；不会自动补发历史授权。部门变更影响预览不是权限实现，提交仍重新计算。

媒体默认建议鉴权代理，每次Range重新校验；如果改短效签名地址，应记录撤销后最长残余窗口并实际测试。已下载副本无法远程抹除。Web退出清除本地敏感缓存和播放器；共享平板维护态退出清理会话和回退栈。

自动快照等待发送期间，账号停用、范围收紧、删除或目标停用会阻断当前待发；普通更正只生成新版本，不使初始快照失效也不新建发送，宽松目标配置只作用新会议；worker执行前检查。系统自动规则需要明确的配置授权责任与有效版本，不能永久借用离职员工会话，也不依赖发起人在场。

## 6. 威胁与对应措施

| 入口/风险 | 设计措施 | 必需验证 |
| --- | --- | --- |
| 猜会议/资产ID | 所有内容服务对象授权，未知与无权不泄露 | 更换ID/Range/导出请求拒绝 |
| 角色编辑、加组间接提权 | 委派范围和受影响授权整体核对 | 设备管理员自授正文、跨部门授予被拒 |
| 上传路径/异常媒体 | 随机私有存储键、大小/格式/解析限额、解析进程隔离方案 | 路径穿越/伪装格式/超量请求 |
| XSS/危险链接 | 不可信正文文本化/受限格式，外链不自动访问 | 标题/纪要/日志中的可执行片段不执行 |
| Webhook任意目标 | 批准目标域协议校验，凭证后端保存 | 内网地址/跳转/密钥回显拒绝 |
| 备份与运维越权 | 独立恢复权限、密钥与数据分开控制、审计 | 恢复不复活停用/撤权、无全量正文默认开放 |

安全实现以选定架构的当前官方实践核验；本文件未声称已完成渗透测试或法律合规审查。

## 7. 验证与交付

交付认证时序、会话/设备凭证生命周期、完整权限矩阵、委派初始化/恢复操作、缓存撤销窗口、审计事件规范。以真实请求验证多用户/多组/跨部门/受限会议，包含“全公司只读＋销售编辑≠财务编辑”。详见TC-SEC、TC-IAM及ACC-02。

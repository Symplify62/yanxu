# BASE-01｜已确认业务基线与剩余条件 v1.3

## 1. 当前依据

U-01至U-10的历史需求与文档迭代见旧v1.2包；U-11为本次grilling访谈和整体回放后Alec明确“确认”。本文件是当前业务基线。用户已确认的规则如下，不再标成待选路线。

| 项目 | 已确认规则 |
| --- | --- |
| 使用场景 | 单公司内部，首期一间会议室，通常五人，中文 |
| 身份 | 企业微信有效员工登录；首次自动开通基础账号，采用组织信息 |
| 平板 | 每场员工手机扫码；开始/暂停/继续/结束；本地保存成功后自动退出员工，设备任务继续 |
| 归属 | 默认发起人主部门，可在开录前改到有权范围；冻结后不因后续调岗改变 |
| 正常主流程 | 结束→自动上传→转写→AI总结/事项→固定规则自动发群，无人工核对/审核/确认发送 |
| 接收群 | 管理员按部门/业务范围配置；员工不任意选群；平板无本场不发群开关 |
| 查阅 | 员工可在公司内外用手机查看本人或明确授权会议；四类资料生成即可看 |
| 共享与更正 | 发起人可授公司内只读查看权、撤销自己授出的权；可选手机更正，保存不自动重发 |
| 下载 | 在线查看/回听不等于下载；原音频下载和导出独立授权 |
| 录音时长 | 不设业务时长上限；实际设备资源有限，持续能力必须测试 |
| 数据处理 | 允许音频/文字采用选定外部AI；具体服务商/数据条款/预算与真实接入仍需落实 |
| 保存 | 公司四类档案长期保存，默认不按期删除；设备缓存另设受控清理条件 |
| 故障 | 先自动恢复/重试；无法恢复由管理员处理；现场采集/保存故障立即告知现场人员 |

Q2/Q7/Q8早期人工核对方案已被后续“尽可能自动化”的明确要求取代。当前不保留普通待审核队列、用户选择仅归档/审核模式或保密开关。管理员应急停发、撤权、删除及配置变更仍为受控维护操作，不是每场员工步骤。

## 2. 授权与实施状态

本轮授权同步文档、页面级规格、原型及测试关联；未开始真实企业微信/AI/数据库/安卓/群接入。文档“业务已确认”不表示已验证技术能力或获得任意供应商/真实群/费用授权。

G0合成开发与原型；G1真实业务录音须落实告知、身份、网络、存储与备份责任；G2真实外部AI须确定服务、资料边界与预算；G3真实群须确定受众、凭证和手机访问；G4长期试点须完成指定设备、容量、恢复和完整场景。已确认规则不在每场会议重复审批，门禁只用于实际系统启用与变更。

## 4. 安全初值与变更

真实AI/群出口在部署获批前关闭，原型始终模拟；已配置且允许的普通会议运行AUTO。普通员工没有“禁发本场”配置；全局应急停发归管理员。数据长期保存不允许后台擅自按期清理；设备缓存必须满足归档/备份/授权条件。

技术准备见DEC-01；业务变更登记版本、理由、影响REQ/用例和批准来源。不得用修改规则掩盖实现缺陷。参见CHG-01了解v1.2→v1.3的替代关系。

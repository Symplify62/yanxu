# PRD-02｜上传与音频归档

## 1. 目标与业务定义

本模块负责“音频从设备到受控存储”，不依赖 AI 成功。原始录音指实际采集并封存的源文件或源片段集合；为播放生成的拼接/转码文件是派生件，不能覆盖唯一原件。服务端完整接收不等于备份完成，备份完成也不等于永久保留。

每场先联网验证员工扫码身份并取得本场采集绑定；此后本地录制、封存与已有待传任务可在断网时继续，恢复网络后上传。不可离线匿名创建新场再补填人员。请求路径、分片大小、对象存储选型属于设计，不采用历史 Wave 的字段作为强制契约。会议室和设备身份以服务端授权核对，不能信任客户端任意填入的归属。

## 2. 管理界面

UP-01 上传队列显示会话编号、采集结束时间、字节进度、校验状态、重试计数和可操作错误；百分比代表传输进度，不能替代校验通过。UP-02 文件诊断显示音频大小、可播放时长、片段清单、缺口、服务端保存证据和备份时间，不向无内容权限维护者提供播放入口。

## 3. 功能需求

### REQ-UPL-001｜会话、身份与幂等归档

**范围：P0；依据：U-11 已确认业务＋实施细化。**

以认证设备＋client_session_id去重，并验证服务器签发的本场扫码绑定；上传携带不可冒用的员工和归属依据。员工结束后会话注销，不影响设备用既定采集绑定上传本场已录资料。

**反馈与例外：**不能靠客户端任意填initiator/department获得归属；离职/停用后设备仍可保全已录原件，但停用人不可登录访问，自动发送重新按当前策略检查。

**验收：TC-UPL-001, E2E-004。**

### REQ-UPL-002｜完整接收与收据

**范围：P0；依据：建议细化。**

完整接收应校验清单、片段大小/完整性、文件可读性及存储与会议记录持久性。完成后生成稳定接收收据，独立排队后续任务。不等 AI 返回才答复上传。

**反馈与例外：**收到请求或缓存完毕不是最终接收；部分内容存在时保持待完成/不完整状态。

**验收：TC-UPL-002, E2E-001, E2E-005。**

### REQ-UPL-003｜中断续传与有界重试

**范围：P0；依据：建议细化。**

网络变化时保留待传范围，支持分段或等效可恢复上传。采用可配置的有限重试和退避，认证失败、非法文件不进行无意义无限重试。重启后恢复队列。

**反馈与例外：**网络不可用显示待网络；达到自动重试上限转管理员处理，原件保留。

**验收：TC-UPL-003, E2E-002, E2E-005。**

### REQ-UPL-004｜标识相同内容不同的冲突

**范围：P0；依据：建议细化。**

同设备同会话或片段标识但内容摘要不同，标为冲突并隔离新副本，不覆盖既有原件。管理员根据证据选择保留为独立恢复件或拒绝，必须留痕。

**反馈与例外：**不得仅以最后上传时间胜出；冲突会议自动处理和分发暂停。

**验收：TC-UPL-004, E2E-004。**

### REQ-UPL-005｜片段、暂停与完整性

**范围：P0；依据：建议细化。**

存储录音会话清单，包含片段顺序、采集边界、暂停和异常缺口。拼接或衍生播放文件必须可回溯至原片段。声学静音不自动算缺片；缺片不以静音填充后伪称完整。

**反馈与例外：**原始片段可回放的范围应明确；人工接受不完整记录也不能抹掉缺口标记。

**验收：TC-UPL-005, E2E-003。**

### REQ-UPL-006｜并行会议与资源隔离

**范围：P0；依据：建议细化。**

上一场正在上传或处理时，新会议仍可开始；旧任务不能占用采集资源到导致新录音丢音。所有状态及文件按会话隔离，失败不影响其他会议。

**反馈与例外：**首期并行度可低，但不得设计为只能等纪要结束才录下一场。

**验收：TC-UPL-006, E2E-017。**

### REQ-UPL-007｜本地原件清理与长期档案

**范围：P0；依据：U-11 已确认业务＋实施细化。**

公司服务端长期保留原音频和所有文字资料；默认不按期限自动删除业务档案。平板本地缓存仅在归档、独立备份和批准设备空间策略均满足时可清理，不以服务器长期保留要求无限占满平板。

**反馈与例外：**设备缓存清理参数仍待实测与配置；未归档、冲突、唯一副本和保留锁资产不得自动清理。

**验收：TC-UPL-007, E2E-017, E2E-030。**

### REQ-UPL-008｜上传安全与限额

**范围：P0；依据：建议细化。**

设备仅能上传自身授权内容；验证真实格式、大小、清单长度，限制异常压缩/解析资源。文件名作为显示数据，不作为服务端路径。存储私有，不允许裸地址匿名读取。

**反馈与例外：**拒绝原因可诊断但不泄露密钥和存储路径；任意 URL 导入不是首期入口。

**验收：TC-UPL-008。**

### REQ-UPL-009｜撤销设备与恢复数据

**范围：P0；依据：建议细化。**

设备被撤销后停止普通上传与获取业务信息，但本地原件不销毁。提供管理员批准的受控恢复流程，验证归属、清单与隔离区，不能通过“恢复模式”绕过身份校验。

**反馈与例外：**断网设备无法即时感知撤销是已知边界；重连拒绝须提示联系管理员而非循环删除重建。

**验收：TC-UPL-009, E2E-016。**

### REQ-UPL-010｜原件与派生件的生命周期

**范围：P0；依据：建议细化。**

原件、播放文件、转写导出、纪要导出分别记录来源与保留规则。替换算法或重新转码创建新派生件；删除会议应按 NFR-01 覆盖关联物、索引、待处理任务和备份恢复删除清单。

**反馈与例外：**处于调查/业务保留锁时暂缓物理删除并记录原因；不能把“回收站隐藏”显示为彻底删除。

**验收：TC-UPL-010。**

## 4. 最小数据与业务响应

会话接收结果至少含稳定会议标识、原设备会话标识、接收状态、完整性状态、缺失/冲突清单、确认时间和版本。上传错误分为可重试、需要重新授权、输入冲突、永久非法四类。开发人员在接口设计中落实具体状态码与错误结构，不以全部返回成功码掩盖失败。

上传后的录音转写失败，应保持“已归档、处理失败”。对于完整音频和缺失转写，不得拒绝保存原件。对已知不完整音频允许隔离归档及人工恢复，但不默认自动分发。

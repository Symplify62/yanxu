# ACC-02｜工程测试与发布验证

版本1.3-draft；工程测试方案，未执行正式产品测试。沿用ACC-01的L1至L5与现有128个TEST用例，不重新编造一份通过清单。机器业务索引见requirements；本版文档校验与独立阅读审查单独保存在evidence。

## 1. 验证层次与职责

| 层次 | 输入/方法 | 主要证明 | 不能证明 |
| --- | --- | --- | --- |
| 规则单元 | 合成权限/状态/时间/版本案例 | 角色范围成对、历史边界、路由优先级、版本规则 | 接口或存储实际安全 |
| 接口/数据库集成 | 临时测试库、私有测试资产、真实请求 | 认证/查询范围/唯一约束/事务/文件收据 | 真机收音或真实企微 |
| 异步与故障 | 双worker、进程终止、超时/乱序、重复事件 | 领取、去重、未知结果、恢复和迟到保护 | 任意外部系统恰好一次 |
| Web端到端 | 真实浏览器、多身份、接口与页面 | 登录回跳、编辑与自动发布、媒体/搜索/导出和撤权 | 只有mock时不能证明后端 |
| Android/AVD | 明确宿主采音或文件注入 | 生命周期、界面/队列、本地文件 | 目标平板麦克风与省电行为 |
| 真实服务/设备/会议室 | 批准样本、账号、群、实际平板 | 指定环境的完整结果、质量、网络和长期行为 | 未测试设备/规模 |

测试框架在T-10结合选定工程确定；复用工程已有框架，不为本方案指定多个重复工具。开发负责自动化和重复验证；业务负责人确认实际规则与可接受效果。

## 2. 核心跨模块场景

| 验证场景 | 要检查的实际证据 | 关联需求族 |
| --- | --- | --- |
| 开始→本地保存→归档→回听 | 实际文件/清单/收据、播放、状态时间 | REC/UPL/LIB |
| 连续两场、前场仍上传 | 设备会话唯一、无串音/串文、资源不压垮采集 | REC/UPL |
| 响应丢失/重复上传/内容冲突 | 唯一会议、原件摘要不变、稳定收据、隔离冲突 | UPL/NFR |
| 全公司只读＋销售编辑 | 财务可读不可编辑；搜索/导出/媒体同样限制 | IAM/SEC/LIB |
| 停用、移组、调岗、撤权 | 旧会话/旧URL/Range/缓存/后台任务的当前结果 | IAM/SEC |
| 用户编辑同时AI迟到 | 人工版本保留、来源标记、无静默覆盖 | AI/LIB |
| 自动快照冻结后改内容/目标/范围 | 发送前检查当前安全约束、保持旧快照、修改不自动重发 | DIST/IAM |
| 群请求可能成功但响应丢失 | UNKNOWN、停止自动重发、人工核对记录 | DIST |
| 删除后任务结束/旧备份恢复 | 无新发布、已删不复活、已发不重发 | SEC/NFR/UPL |
| 长录音/上下文超限 | 首中尾覆盖、缺口/重叠去重、实际耗时/成本 | REC/AI/NFR |

每个场景至少包含正向、拒绝/失败和恢复；保存数据库截图不代替实际接口响应，页面禁用不代替服务端拒绝。

## 3. 样本与可复现性

复用ACC-01样本分类，生成明确授权的音频及人工标注；合成文字不当作ASR样本。样本登记来源/许可、用途、摘要、时长、噪声、语言、预期关键事实、可外发范围和清理策略。训练/调试用例与最终验收样本分开。

测试身份至少包括：仅设备维护、仅业务查看、销售编辑＋全公司只读、业务授权者、停用用户、无任何资格、同名不同外部身份。资料包括普通、受限、未归属、缺口、无语音、已发后修订、已删除和有保留锁。

记录输入版本、代码提交/构建、环境、配置/模型版本、请求/事件关联标识与结果。日志避开密钥和会议全文；必要音频证据使用受控位置。

## 4. 界面与可用性

按DES-05组件状态和DES-06页面清单验证加载/空/错误/无权/过期/冲突，不只拍首页。桌面宽屏、笔记本、窄屏和实际安卓触控分别验证。键盘焦点、弹层关闭、中文长文本/大字体、音频定位与可操作错误要有证据。

视觉基线或快照只能发现外观变化，关键动作仍需端到端断言。原型v0.2的33项交互＋3项模型/渲染检查是历史原型证据，不能搬成真实产品通过。

## 5. 持续集成与发布顺序

代码变更运行影响范围内类型/静态检查、规则/组件与接口测试；数据库/上传/任务/权限变更增加集成与故障验证；可见交互变更增加对应浏览器/设备路径与截图。依赖和配置检查针对实际使用组件与环境，不通过关闭失败测试换绿灯。

候选发布：可重复构建→测试环境迁移/安装→核心端到端→故障与恢复→实际服务/指定设备必要层级→发布审查。正式发布后回读实际版本及批准范围内业务。测试通过不自动授权外发或生产。

## 6. 指标和判定

错误必须按实际失败保留；性能记录样本数、硬件、网络、并发、最长/分位，AI记录质量/覆盖/时延/费用。目标值取D-01/D-10/D-12/D-13批准记录，不把开发示例阈值当承诺。

阻止试点的严重问题沿用ACC-01：原件丢失、权限绕过、无批准外发、不可控制重复消息、核心完整性错误。缺资源的测试标未执行/阻塞，并注明影响范围；无关切片可继续。只完成低层级时不能把高层级勾为通过。

## 7. 每阶段证据与交接

每次运行：run_id、需求/测试ID、提交/构建、输入/环境、步骤、预期/实际、结果、证据引用、缺陷与复测、是否真实调用/费用。结果写到DEL-03和需求追踪，不修改PRD来适应失败。

发布验证还需签名APK/服务构建、迁移记录、依赖版本、配置摘要、备份/恢复/回退证据和真实负责人。文档结构校验、独立阅读审查、原型验证与正式产品验收分别记录。

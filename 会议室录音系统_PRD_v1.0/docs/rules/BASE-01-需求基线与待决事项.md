## 2. 优先级、状态与门禁

P0：首期生产试点前必须实现和验证。P1：明确可后置增强。范围之外的项目不能暗中加入。需求确认状态（已确认目标/建议细化/待决）、实施状态（未开发/实现中/已实现）、验证状态（未执行/通过/失败/不适用）分别存储。

G0：隔离开发可开始，只使用合成/授权测试数据，默认禁真实外发与删除。

G1：可以处理真实业务录音前，必须批准告知方式、身份/内容访问、服务器位置、保留/备份策略与设备测试范围。

G2：调用真实外部 AI 前，必须批准服务商、数据类型、地域条件、样本、预算和失败策略。G1 不自动授予 G2。

G3：向真实群发业务内容前，必须批准目标受众、连接、模式、完整记录可达性和访问校验。

G4：长期无人值守试点前，完成实机、会议室、容量、异常与恢复验收。不存在“只差买平板，但已生产验收”的状态。

待决事项未解决不阻止无关模块在 G0 开发；但到相应门禁时必须停止相关危险动作。开发人员不能将“待定”改成自己的生产默认值。

## 5. 变更申请

变更记录必须包含原需求、原因、新行为、替代方案、影响需求/用例/数据、成本与风险、批准人和生效版本。修正文档拼写不等于变更业务。改变发送、数据去向、保留或权限需要明确批准。配置发布属于受控业务变更，不是绕过需求签核的后门。
